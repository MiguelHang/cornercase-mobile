# Changes and files

A workspace's git changes from the phone, usually an agent's worktree: the list of changed files, a file's diff, and its viewed mark, which the Mac's changes panel shares (task 025); and its files, read-only: the tree, a file's text or picture, and a search by name (task 026, Files). Code: `crates/core/src/cli/changes.rs` (the types and the argv), `crates/core/src/changes.rs` (following the list), `crates/core/src/follow.rs` (the reopening loop the terminal shares), `src-tauri/src/commands/changes.rs`, `src-tauri/src/commands/reach.rs`, `src/lib/changes.svelte.ts`, `src/lib/diff.ts` and `src/routes/changes/`. Upstream's `design/commands-for-scripts-and-agents/changes.md`, `src/cli/args/changes.rs` and `tests/fixtures/control/changes/v1/`, and gpui's `design/changes-panel.md` and `src/panels/changes/`, were read on 2026-11-09 (upstream at 425b3ae1, which matches 0.13.19 for these files). The files' code: `crates/core/src/cli/files.rs`, `src-tauri/src/commands/files.rs`, `src/lib/files.svelte.ts`, `src/routes/files/` and `src/lib/ui/CodeBox.svelte`, which the diff shares; upstream's `design/commands-for-scripts-and-agents/files.md` and `tests/fixtures/control/files/v1/` were read on 2026-11-10, the same at 3916d6cf and on `origin/main` at d24b956d (0.13.26).

## What is read

- **One type for `changes list --json` and every line of `changes list --follow`** (`Summary`, `ChangedWorkspace`, `ChangedFile`): upstream prints the same object both ways. `changes file --json` is a `Patch`: the file's fields flattened beside `workspace`, `mode` and `hunks`, whose lines carry `kind`, `old`, `new`, `text`, `raw` and `emphasis`.
- **Read leniently, as gpui's `wire.rs`**: every struct is `#[serde(default)]`, unknown fields are ignored, and each closed enum (`State`, `Status`, `Fold`, `Staged`, `LineKind`) has an `Other` (`#[serde(other)]`), so a value a newer cornercase adds reads as `Other` instead of rejecting the line. The UI shows `?` for a status it does not know and a line of an unknown kind as context.
- **`styles` and `syntax` are not read**: they are indexes into the Mac terminal's palette, which the phone has only inside a `surface`. Highlighting is left out (Left out).
- **The digest is text**, 16 hex digits, never a number: upstream sends it as a string because JSON numbers lose precision past 2^53 in JavaScript, and the app hands it back as it came.
- **Fixtures copied byte for byte** from upstream's `tests/fixtures/control/changes/v1/` (`summary.json`, `patch.json`, `every.json`) to `crates/core/tests/fixtures/control/changes/v1/`, read through `cli/changes/fixtures.rs`.

## The commands

- **`changes list --follow --workspace W --mode M`** for the list, **`changes file --workspace W --mode M --json -- PATH`** for a diff, **`changes viewed --workspace W --digest=D -- PATH`** to mark and **`changes viewed --workspace W --clear --mode M -- PATH`** to clear. `--` before the path and `--digest=` keep a path or a value that starts with `-` from being read as an option, as in Starting work.
- **`Mark { Seen { digest }, Clear { mode } }`**, so the type rules out what clap refuses: `--digest` conflicts with `--clear` and with `--mode` (the mode only chose which version a read showed), and clearing takes no digest. `changes_viewed` with `viewed: true` and no digest answers `no_digest` without sending anything.
- **The mode is the screen's**: upstream gives each stream its own mode, and `changes-mode` changes it only on the connection that holds the stream, which a CLI invocation never is, so another mode is another stream.

## Following the list

- **`--follow`, not `events`**: the app's `events` stream says nothing of git (no event when a file changes), so reading again on events would miss every edit. `changes list --follow` sends a whole new summary each time the files change, at most every 100 ms, and asks git at most once a second; the ticket allowed either, and only this one keeps the list live.
- **One stream per workspace and mode** while the list (or a diff over it) shows, in a slot of `Active` of its own (`follow`, `unfollow`), apart from the terminal's, so a diff and a terminal never stop each other. Following another workspace or mode replaces the task, `unfollow` of another workspace leaves it, and connecting again or removing the machine ends it with `Active`. Each summary replaces the list; none is a patch.
- **A first `loading` without files is ignored once a list was sent** (`only_starting`): every stream opens with one while git runs, and after a reconnection it would empty the list for a moment. The first open, and a new mode, show it as the spinner.
- **Opened again like the terminal** (Terminal › Opening it again), through `follow::reopen`, whose loop (`follow::revisit`) `Terminal::run` shares: wait until the `Store` is `Connected` with a session; a workspace missing from it ends the screen (`Closed`); otherwise open the stream on the `Store`'s transport, and drop it once the `Store` is no longer connected on that transport. After any end it waits a second (`SETTLE`) before looking at the session again, since a stream ends with `Detached` (workspace closed, project closing) or status 0 alike, and a restart closes nothing until a new session lists the workspace. Rejected: a second copy of the loop for the changes, which jscpd refuses and which could drift from the terminal's.
- **`state: failed` is a summary** (a folder that is not a repository, git's error): the screen shows its `error`, and the stream stays open, since cornercase sends a new summary when that changes; nothing retries in a loop. A line that does not parse, or a stream that fails, is a warning, once per run of failures, as an error `toast`.
- **`changes-changed { machine, workspace, mode, summary, closed }`**: a summary, or `summary: null` with `closed: true` when the workspace is gone, and the screen says `This workspace was closed on the Mac` and rests. The UI drops an event of another machine, workspace or mode. Failures go out as `toast`, the `Store`'s path, rather than a field of the event.

## Reading a diff

- **One-shot, on the transport**, as the chat's `last_message`: `changes file` writes nothing, so it does not wait behind sends in the queue.
- **Read again when its file's `digest` changes** in a summary that is `ready`, so an agent's edit shows without a tap; the digest kept is the row's at the time of the read. When the file leaves the list, the diff says `<path> no longer has changes` (with an `info` toast) and is not read again.
- **The newest read wins**: each read and each close takes a generation, and an answer of an older one, or for another file, is dropped (two quick taps, a read under a newer summary).
- **`binary` and `too large`** come without hunks; the screen says so in the diff's place. A `lockfile` is read and shown like any file, with its tag in the list.

## Viewed

- **Through the ordered queue** (`Queue::ask`), as every write: `Skipped` is `not_sent` and `Unanswered` `maybe_sent` (`commands/reach.rs`, which the chat and the start screen share), and the UI takes the reason as the chat does (`deliver`).
- **Optimistic**: the mark flips at once. A failed command takes it back to what the list said and shows the reason in an error toast. Once the command answered, the next summary decides (it carries the marks), so a mark another client changed meanwhile is not overwritten; a mark still on its way stays over the summaries that come before its answer.
- **The digest sent is the version shown**: the patch's while its diff is open, else the row's. It depends on the mode (Uncommitted's is a fingerprint of the file's metadata, Commits' and All's the patch's), while the mark is per file and shared by the modes, so it is the digest of the mode on screen.
- **A digest that is no longer current answers OK and marks nothing**: upstream stores marks without reading the file, so `changes-viewed` gives no `conflict`, and a digest read while the file was being written names no version at all. There is no error to take back; the next summary shows the file unmarked. Accepted: the alternative, reading the file again before marking, narrows the race without closing it, as upstream says.

## The screens

- **`changes`**, pushed by the agent's `Changes` (Chat › The screen) with the workspace and the name of its row: the name, `+N −M` for the workspace, the three modes (`Uncommitted` by default, `Commits`, `All`), one row per file and the states. Three modes because an agent that has already committed in its worktree leaves Uncommitted empty, and the work to review is in Commits, against the base. Empty, it says `No uncommitted changes`, `No commits ahead of <base>` or `Nothing changed since <base>`.
- **A row**: the status letter (`M`, `A`, `D`, `R`, `U`), the path or `old → new`, the `lockfile`, `binary` or `too large` tag, `+a` and `−r` when not zero, and the viewed box (`square`, `square-check`), a 44 px target of its own beside the row's button, which opens the diff. A viewed row is dimmed.
- **`change`**, pushed over it: the path in the header, cut at its start (`direction: rtl` with the text `ltr`), the viewed box, and the unified diff: each hunk's `@@ -a +b @@ context`, then each line with its old and new numbers, its sign and its text.
- **One box scrolls sideways, whole**: lines never wrap (`white-space: pre`), since a wrapped diff on a phone loses its columns; the numbers' gutter is `position: sticky` at the left, so they stay while the text scrolls. Added and removed lines take `--diff-added` and `--diff-removed`, and the words that changed (`emphasis`) the `-strong` tints: `--done` and `--failed` at 10 % and 32 %, tokens of our own, since gpui's theme has none for a diff.
- **`emphasis` counts characters**, Unicode scalar values as upstream does, so the text is split with `Array.from` and never by UTF-16 units, which an emoji would shift.
- **The `ChangesState` lives on** while `changes` or `change` is on top (`Router.reviewed`), so going back from a diff keeps the list and its stream; the agent's `Chat` lives on under both (`Router.opened`). Leaving the list unfollows. Its `changes_follow` and `changes_unfollow` are ordered as the terminal's `Opening` orders its calls (Terminal › Opening it): `changes_follow` is asynchronous in Tauri and `changes_unfollow` is not, so an unfollow sent right after a follow could run first and find nothing in the slot, and two follows sent at once (a quick switch of mode) could reach the slot in either order and leave the mode no longer shown. So the follows go one after the other (`#turn`), each skipped once the screen has left or another mode was asked for, and one that answers after the screen left is unfollowed again. The diff's `change` route carries no mode: the diff shows in the `ChangesState`'s, the list's. Limit: a list opened again on the same workspace before the last one's `changes_follow` answered is unfollowed by it and waits until the mode changes; telling them apart would need a token from `changes_follow`.
- **A large diff is all in the DOM**: no virtual list. Upstream already folds a file that is too large, so what comes stays within its limit; noted here to look at should a long file scroll slowly.

## Files

### What is read

- **`files list --json`** is a `Listing` (one `Folder` per path asked, each with its `entries`, `more` and `error`), **`files read --json`** a `Read` (its `kind`, the `text` or the `image` with its format, width, height and base64 `data`), and **`files search --names --json`** a `Found` (each path with the `indices` it matched, `matches`, `capped`). Read leniently as the changes are: every struct `#[serde(default)]`, and `EntryKind`, `ReadKind` and `SearchMode` with an `Other`; the git letter is the changes' own `Status`. `boot`, `stream` and `revision` are not read: the app follows no stream of files.
- **Fixtures copied byte for byte** from upstream's `tests/fixtures/control/files/v1/` (`listing.json`, `text.json`, `image.json`, `search.json`) to `crates/core/tests/fixtures/control/files/v1/`, read through `cli/files/fixtures.rs`.

### The commands

- **Every path goes after `--` and starts with `./`** (the root is `.`), as gpui sends them: a name that starts with `-` is not an option, and one that starts with `~/` is not the server's home, which upstream expands for `files` so a path can reach outside the workspace. The app shows only the workspace, so it never sends a path that leaves it. The search's query goes after `--` too.
- **A partial answer is an answer**: `files list` exits 3 when a folder failed and `files read` exits 1 for `missing` and `folder`, both after printing the whole JSON. So `files::partial_json` reads the object from stdout whatever the code, except `stale-boot`'s, and only when stdout holds none gives the failure (`Failed { code, stderr }`). Rejected: `transport::json` as it is, which would turn a folder without permission or a deleted file into a failure of the whole call.
- **One-shot, on the transport**, as `changes file`: none of them writes, so none waits behind sends in the queue. `files list` takes every path in one call, so the tree is read again in one round trip.
- **A new search ends the last one**: `files_search` keeps its task in a slot of `Active` of its own (`search`), and filling it aborts the task it held. Dropping that future closes the bridge's WebSocket, the bridge ends the process (Bridge), and the server cancels a search whose client left, so a fast typist leaves no walks running on the Mac. The aborted call answers `Cancelled`, which the UI ignores; a generation in `FilesState` also drops an answer that arrives after a newer query. The field waits 200 ms after the last key before it asks, and a blank query asks nothing (upstream refuses it as `malformed`) and shows the tree again.

### Limits

- **The phone's own limit for text: 1 MiB or 20,000 lines** (P2), on top of the server's 8 MiB. Past it, `files_read` answers `TooLargeHere { bytes, lines }` without the text, in Rust, so the text never crosses IPC: the viewer has no virtual list, and a DOM of several MiB of lines would stall the WebView. The screen says `Too large to show on the phone (3.0 MiB, 25,000 lines)`. The numbers are a first guess, to be tuned after the live check.
- **The bridge's 16 MiB per line** (Bridge › A line of 16 MiB at most): `files read --json` prints an image's base64 in one line, a third bigger than the picture, so an image over about 12 MiB (the server reads them up to 32 MiB) ends in exit 2 with `a line of output passed 16 MiB`. `files_read` turns that into `too_large_here`, `Too large to show on the phone`, rather than a generic failure. A text of 8 MiB fits, unless it holds many control characters, which JSON escapes in six bytes each. It is the bridge's limit, not upstream's, so it is not a gap: `/cli` will have its own.
- **SVG is text**: upstream tells a picture by its first bytes and an SVG has none, so it reads as `text` and the viewer shows its source. Rendering it as a picture was left out: the app follows the server's `kind`, and a picture made of markup could ask for what the CSP refuses.

### Freshness

- **No `--follow`**: upstream's `files list --follow` is one stream per connection, which a new folder opened would restart with every path, and through the bridge each stream is a process; gpui rejected it for the same reason. So the screens read again at the moments that matter: back from a file to the tree, `files list` reads the root and every open folder again in one call; opening a file always reads it again; and the tree, its open folders and the query live while `files` or `file` is on top (`Router.browsed`), as the `ChangesState` does. Accepted: a tree left on screen does not change by itself while an agent writes.
- **Started untracked**: `App`'s effect starts the `FilesState`, or reads the file it opened on, inside `untrack`. `start` reads the folders it then marks as loading, so a tracked effect ran again at once, its cleanup stopped the state, and the answer was dropped: the tree spun on `Reading the files…` for good (found in the live check, below). The `ChangesState` escapes it because it starts in a `.then`, outside the effect's run.
- **A workspace that is gone**: the CLI gives no code for it, so the server's reasons (`there is no workspace W;`, `workspace W is closing`, `is being removed`) say so; the screen then shows `This workspace was closed on the Mac.` with an info toast, and rests. Any other failure shows in the screen (the search's, the file's, or a folder's in place of its children) and as an error toast. Limit: unlike the changes' stream, which opens again only on a session that lists its workspace, the files screens do not look at the session, so after a server restart a reused workspace id can be read (Upstream gaps).

### The screens

- **`files`**, pushed by the agent's `Files` (Chat › The screen) with the workspace and the name of its row: `Back`, the name, the search field, and the tree. **A tree that unfolds in place** (P1), 16 px deeper per level, as the Mac's panel and gpui draw it. Rejected: a screen per folder, as the Files app does, which would read each folder on its own screen, while one call reads again everything open, and would look unlike the board's folds.
- **A row**, in the server's order (folders first): the chevron for a folder, its icon (`folder`, `folder-open` when open, `image` for a picture's extension, else `file`), the name, the git letter with the changes list's colours (`?` for one it does not know), dimmed when hidden, and a `link` tag; an entry that is neither a file nor a folder does not open. `more` says `Only the first 10,000 entries`, and a folder's `error` stands in for its children without hiding the rest. Every row is a 44 px target. A link to a folder is a folder; a broken link is `other`.
- **The search's results** take the tree's place while the query is not blank: each path, cut at its start, with the characters of `indices` in `--accent`, counted as characters (`Array.from`) as `emphasis` is; `Nothing found`, and `Only the best 200` when `capped`. A tap opens the file.
- **`file`**, pushed over `files` (or over `change`): the path cut at its start, as `change`, and the text with a number on each line in the diff's box, scrolling sideways whole with the numbers sticky (The screens above), now `CodeBox`, which both draw, so neither copies the other (jscpd). Lines split at `\n` and `\r\n`, and a last line break makes no empty line. A picture is an `<img>` of a `data:` URL (PNG, JPEG, GIF, WebP, BMP; the CSP already lets `img-src` take `data:`), at its own width and height and no wider than the screen. In the content's place, a line says why there is none: `Binary file, not shown`, `Too large to show (12 MiB)`, `<path> no longer exists`, `<path> is a folder`, `Not a file, not shown`, the phone's limit or the failure.
- **From a diff, the whole file**: the diff's header has `Whole file` (`file-text`), which pushes `file` with the new path of a rename. It is not offered for a deleted file, which the disk no longer has, nor while the diff loads or its workspace is gone. `Router.reviewed` looks for the last `changes` or `change` above the chat, not only the top, so the `ChangesState` and its stream live on under `file`, and `Back` comes back to the diff as it was. **The viewer shows the working tree as it is now**, also from the `Commits` and `All` modes, whose diff is against the base: the whole file may hold uncommitted edits that diff does not show.

### Highlighting

- **Plain text, as the diff** (P3). Measured on 2026-11-10 with `pnpm build` (Vite 8.3.6): `dist/assets/index-*.js` was 256.6 KB (82.4 KB gzipped) before the files screens and is 271.6 KB (86.3 KB) with them. highlight.js 11.12.0, its core with twelve grammars picked by the server's `language`, bundled and minified on its own, is 66.0 KB (21.0 KB gzipped), its core alone 21.1 KB (8.3 KB): about a quarter more script, before a theme in our tokens and a split that keeps a token's spans across the box's lines. No bundle budget exists in `docs/` or `design/`, the diff has no highlighting either (`styles` and `syntax` are the Mac palette's), and the ticket made it optional; so it waits for a budget or for users asking. `Read` keeps `language`, so it needs no change of the core.

## Left out

- `changes gap` (the unchanged lines between hunks), `stage`, `unstage`, `discard`, `base`, `merge-check`, `shared`, `--every` and `changes-mode`.
- Highlighting (`styles`, `syntax`), copying a line (`raw`), selecting, asking an agent, opening in an editor and a filter by text.
- Files: `--follow` (Files › Freshness), the search by text (`--text`, whose `files` and lines the types read anyway), finding inside the open file, selecting and copying, opening in an editor, asking an agent, git's marks in the viewer's margin, paths outside the workspace (absolute or `~/`), and a switch for hidden files (P4: they show dimmed, as on the Mac's panel).
- A workspace without an agent: the board lists only agents, so there is no way in yet, to its changes or its files.
