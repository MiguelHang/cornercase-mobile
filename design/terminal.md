# Terminal

Follows cornercase-gpui's `design/session-model.md` for the `view` and `surface` JSON and for applying frames and patches.

- **Passive by default**: the phone shows a tab with `surface --tab T --cols C --rows R --patches` alone, with no `view`, so the PTY keeps the Mac window's width and the Mac is never resized; the phone shows it with zoom and scrolling. Upstream, a view that is active, sized and showing a tab claims it as it opens (`views.md`, Who sizes a tab), so the `view` with the phone's size and without a claim that task 020 first asked for does not exist: an active one resizes the Mac, an inactive or sizeless one draws nothing and refuses `surface --view`. Rejected: an active `view` with `surface --view` (the Mac is resized on opening), and an inactive `view` kept beside the `surface` for "Fit to this phone" to turn on later (a stream nothing reads until then). The cost: a passive `surface` never counts as seen, so the Mac's `✓` and an agent's notices go on while the phone watches (Upstream gaps).
- **Checked live** (2026-11-09, iPhone Air simulator, iOS 27.2, cornercase 0.13.19 through the bridge): with the screen open on an agent's tab (a stand-in named `claude`, not Claude Code working), the PTY stayed at the window's 87×40, nothing redrew at the phone's width, and the server ran one `surface` and no `view`, opened once and ended on going back. Checked again the same day once the board had taken Home's place (015), through the board, the agent's screen and its `Terminal` button, with a stand-in `claude` turning working and done every few seconds: the screen stayed open and live across those changes of the rows, on one `surface` process all along; the PTY kept its 127×48; `Back` went to the agent's screen and ended the `surface`, and a second `Back` to the board. With the screen open, `kill-server` then `start-server` made it open `surface --tab` again on the new boot, where cornercase had restored the tab with the same id (a new shell, as shells do not survive), and the agent's screen then said the agent no longer runs, with no `Terminal` button.
- **"Fit to this phone"** (task 022) opens a `view` with the phone's size while it is on, which claims the tab as it opens, streams with `surface --view` instead, and closes it (or `view-set --inactive`) when it is turned off or the screen is left. In cornercase, the latest claim sizes the tab and the window takes it back when it is used.
- Rejected: always claiming (the agent redraws at the phone's width and the Mac shows it cropped), never claiming (no way to read at the phone's width).

## The grid

Code: `crates/core/src/cli/surface.rs` (the `surface` JSON), `crates/core/src/cli/view.rs` (a `view` line), `crates/core/src/terminal/` (the grid).

- **Frames and patches are applied in Rust** (`crates/core`, a port of gpui's `model/grid.rs`), tested on Linux; the WebView only gets resolved rows. Rejected: applying them in TypeScript (gpui's logic rewritten and tested a second time, and every patch crossing the bridge whole), and `alacritty_terminal`, a VT emulator that eats a PTY's bytes: cornercase sends cells Ghostty has already parsed, and no command of the contract gives a PTY's bytes, so it would be a heavy dependency with nothing to feed it.
- **The rules are gpui's** (`design/session-model.md`): styles and links resolved on arrival, a patch applied only on the revision, surface and boot it was made from (else `NeedRedraw`, also for a pane the grid does not hold), the order within a pane (cursor always, `active`, `modes`, `scroll` and `colours` when present, `copy` from the lines as they were before it, then changed rows; a key that is not a number skipped). A patch leaves `rect` and `size` alone: cornercase sends a complete frame whenever they change.
- **Where it differs from gpui**:
  - Rows stop at the pane's `size.rows`: a frame's extra lines and a patch's rows past it are dropped. gpui grows the grid to any key, so a key like `"4000000000"` would reserve that many lines on a phone.
  - A run keeps its cells joined (`text`) and how many there were (`width`), not one string per cell: the WebView draws runs, and nothing hits a single cell yet. Tapping a link at an exact column may need the cells back.
  - Every type is `#[serde(default)]`, including a pane, a `copy`, a split's `dir` and the frame itself, so a field cornercase drops never rejects a frame (a split's `first` and `second` stay required: a split without them is no layout).
  - A later value of a closed list never rejects a frame either, as upstream's own clients read a later kind as `other`: an unknown cursor shape reads as `block`, an unknown mouse mode as `none` and an unknown mouse encoding as `default` (`#[serde(other)]` on the default, so the phone sends no mouse it cannot encode), and an unknown `underline_style` as `Other`, drawn as a plain underline. Rejected: refusing them as a change of format, which would blank the terminal of every older app when cornercase adds a cursor shape. A colour (`index` or `rgb`) is still closed: a new kind of colour is a change of shape, not a value.
  - No popup: plugin popups (`surface --popup`) come with a later task.
- **`projection`**: the view (`cli/view.rs`) tells the grid the highest projection it has seen (`saw_projection`), and a grid whose frame carries a lower one is stale. A frame shows when its projection is equal to the latest known **or higher**, where upstream (`views.md`, Projection) says equal: the `view` line comes over another connection and can arrive up to 500 ms after the frame made for it, and with equality that new frame would stay blank until the line came. Rejected: strict equality, as upstream says. A stale frame or patch is still applied, so the chain of `base` and `revision` stays whole, but it shows nothing: `changed_rows` answers no rows. Once a frame or patch makes it current again, it answers every row of every pane, as after a complete frame. Rejected: throwing a stale frame away, which turns every patch made on it into a `NeedRedraw` and a needless `redraw` until the next complete frame.
- **The stream** (`terminal/live.rs`): `Live` runs `surface --tab T --cols C --rows R --patches` on the machine's transport and nothing else, no `view` and no `view-set`, so the tab keeps the Mac's size. The caller pulls it with `next`, which hands the rows each line changed, a warning for a line that is not a surface (the stream goes on) or how it ended: the transport lost (`Lost`), status 0 (`Exited`: the tab closed, the server stopped or restarted, which cornercase does not tell apart) or another status with its error (`Failed`). `next` can be dropped halfway, so the caller can wait on it and on the `Store` at once; dropping `Live` drops the transport's future, which ends the process. On a `NeedRedraw` it asks once for `redraw --surface ID` through the queue and skips every patch until a complete line comes, then hands every row as `replaced`. The queue does not retry a command and drops the one running when it reconnects, so a `redraw` can be lost and the screen would stay frozen while patches keep coming: a patch skipped two seconds or more after the last `redraw` asks for it again. Rejected: asking again on each patch that does not apply, which sends a `redraw` for every patch already on its way and gets as many complete lines back; `ask_coalesced`, clearing the wait on an error, which misses a `redraw` the queue dropped without an answer.
- **Opening it again** (`terminal/live.rs`, `Terminal::run`): `surface` ends with status 0 alike when the tab closed, the server stopped or it restarted, so the end alone says nothing. After any end, `Terminal` waits a second, for the `status` stream to bring the session without the tab or the `Store` to see the new boot, then until the `Store` is `Connected` with a session: a tab missing from it ends the screen with `Closed`, with nothing opened again; otherwise it opens the same `surface` on the `Store`'s current transport and queue, with a new grid and pane choice, so the first complete frame of a new boot replaces everything. A restart, while the `Store` has no session, closes nothing: it waits for the new one, where a tab with the same id is taken as the same tab. The same check runs before the first open. While it follows a `surface`, `Terminal` also waits on the `Store`: once it is no longer `Connected`, or is connected on another transport than the one the `surface` runs on (a return from the background, a change of network, a `Resume`), it drops the `surface` and goes back to that check, as a `surface` whose WebSocket is half open would otherwise freeze the screen until the bridge's silence timeout (45 s) even with the `Store` connected again. Rejected: an end alone, which a half-open socket never brings. A line that is not a surface goes on with the stream. Rejected: opening it again at once, which sees a session still listing a tab just closed; waiting for the next change of the `Store`, which an unrelated event brings too early and a `surface` lost on its own never brings.
- **Telling a failure**: a line that is not a surface, a `surface` that fails (`Failed`) and one lost while the `Store` still holds its transport (`Lost`, else the `Store`'s own state already says it) send `Screen::Failed` with the error, the first time only: it is told again only after a line showed, so a `surface` that keeps failing with the tab still there, opened again every second, tells it once instead of a toast a second. A `surface` that ends with status 0 tells nothing: the tab closed, or the server stopped or restarted, which the session says. Limit: it is still opened again every second, with no growing wait.
- **The terminal in the app** (`src-tauri/src/commands/terminal.rs`): `terminal_open(tab, pane, size)` runs `Terminal::run` on the active `Store` as a task that `Active` keeps; opening again, `terminal_close(tab)` for the tab it shows, connecting to a machine again and removing it abort the task, which drops the `surface` and so ends its process. Without a `Store` it answers `not_connected`. The size is one argument (`{ cols, rows }`) because the command already takes the app and its state, and five arguments is the limit. Each screen goes through a channel to an emitter that sends the first one at once and then at most one `terminal-changed` every 16 ms, a frame: the screens in between are joined, rows by number with the latest winning, a `replaced` dropping the rows before it and staying, the pane, size, cursor and colours of the latest. `closed` comes in the same event, after the rows it held; `pane` is `null` when the event only says it closed, with nothing else, either before anything showed or after the last frame was sent. A `Screen::Failed` becomes an error `toast` with the error's text, as the `Store`'s warnings do, sent after the frame's `terminal-changed`. `rows` is an object keyed by row number. Rejected: an event per line (a busy agent floods the WebView), and waiting a frame before the first one, which delays every keystroke's echo by 16 ms.
- **Colours and styles** (`src/lib/terminal/style.ts`): gpui's `Painter` in TypeScript, with its Tokyo Night palette copied from its `src/theme.rs` (the 16 ANSI colours, bright ones repeating the normal ones, the 6×6×6 cube and the grey ramp), so a tab reads the same on the Mac and on the phone. An index reads the pane's `colours.palette` first, then Tokyo Night; `rgb` is taken as it is; a run without a colour takes the pane's `fg` or `bg`, else Tokyo Night's. Inverse swaps the two after they are resolved, dim draws the text at 0.6 opacity and invisible at 0, as gpui does, so the background stays. A run's style is inline CSS: a background only when the run sets one or is inverse (else the pane's shows through), any `underline_style` an underline, drawn `double`, `wavy`, `dotted` or `dashed` where CSS has it and solid otherwise, in its `underline_colour` when it has one. `overline` and `strikethrough` are lines of the same `text-decoration`. Rejected: a class per style, since 24-bit colours cannot be classes. Limits: CSS draws every line of a run in the underline's style and colour, where gpui draws a strikethrough and an overline solid and in the text's colour, and `blink` is not drawn, as in gpui.
- **The pane in the WebView** (`src/lib/terminal/pane.svelte.ts`): `apply` turns each `terminal-changed` into the screen drawn, one list of runs per row from 0 to `size.rows`: a row it brings replaces that row, a row at or past `size.rows` is dropped, and the rest stay the same objects, so a keyed `{#each}` redraws only the rows that changed. A `replaced` event or another pane starts from empty rows; the size, cursor and colours are the latest event's. An event without a pane only marks the screen closed and keeps what it showed, so the last screen stays under the notice. Colours equal to the ones before stay the same object, since every row is styled from them and a new object each event would redraw them all. Rejected: rebuilding every row on each event, which redraws the whole pane up to 60 times a second while an agent writes.
- **Drawing it** (`src/lib/terminal/Terminal.svelte`, `Row.svelte`, `pinch.ts`): a row is a line of `span`s, one per run, each `width` cells wide and clipping what overflows, so a wide character or a font fallback never shifts the columns after it. The cell is the advance of an "M" in `--font-mono` at the base size, measured once on a hundred of them (0.6 of the size until then, as gpui guesses), inside a box clipped to nothing: the probe is about 790 px wide, and left bare inside the scroller it made the scroller that wide, so on a pane that fits the screen one finger scrolled the grid out of view into an empty right half (found in T11, iPhone Air simulator, iOS 27.2); and the line 1.3 of the size, as in gpui. Both are in `em` (a row is `1lh` tall), so the zoom is the grid's `font-size` alone: the layout grows with it, the scroller's own `overflow: auto` scrolls the wider and taller grid, and no row is drawn again when it changes. Rejected: `transform: scale`, which leaves the layout at its old size, so the scrolling stops short or goes past the grid unless a wrapper is sized by hand. The cursor sits on its cell: `block` fills it, inverting what is under it (`mix-blend-mode: difference`, where gpui paints the cell's text in the background colour), `block_hollow` outlines it, `bar` and `underline` draw a 2 px line, in the pane's cursor colour; `blinking` is not drawn. A pinch zooms from the size at its start, by iOS's `gesturestart`/`gesturechange` (which `preventDefault` so the page itself never zooms, along with the viewport's `maximum-scale=1, user-scalable=no`) or, where they never fire, by how far apart two pointers are; one finger scrolls sideways natively (`touch-action: pan-x`) and up and down through the swipe (Typing › Swiping). The zoom grows from the grid's top left corner, not from between the fingers.
- **The DOM, not a canvas**: checked on 2026-11-09 in the iPhone Air simulator, iOS 27.2, on an Apple M4, with `seq` printing in a loop in the tab shown, the WebView's process used about a fifth of a core while cornercase's server used more than a whole one, so the server, not the drawing, is what limits the rate, and the screen answered a tap within a third of a second. Spans leave the text to the system's font and its fallback for emoji and CJK, and the scrolling and zoom to the layout. Rejected: a `<canvas>`, which draws every glyph by hand, places each cell itself and scrolls by hand, for no gain this check could see. Not checked: a real iPhone, which is slower than the Mac running the simulator.
- **Zoom** (`src/lib/terminal/zoom.ts`): the zoom is a font size in pixels, between the one at which the pane's columns fill the screen's width (the base, 13 px as in gpui, when they already fit at it) and twice the base; the cell width is measured at the base. A tab never seen opens fitted to the width, the whole line in view. The size is remembered in memory per machine, `boot` and tab, since tab ids are reused after the server restarts, and a remembered size is clamped to the limits of now, as the pane or the screen may have changed. Rejected: twice the fitted size as the most (a 200-column pane would stay unreadable), and keeping it on disk, where the ids would outlive their tabs.
- **Opening it** (`src/routes/terminal/Terminal.svelte`, `src/routes/agent/Agent.svelte`): the agent's screen (Board › A row) has a `Terminal` button, 44 px like its `Back`, while it has the agent's row; a tap pushes the `terminal` route over it with the active machine and a copy of that row (`AgentRow`), whose `tab` and `pane` say what to open and whose `boot` is the zoom's place. The route keeps the copy, where `agent` keeps only its machine and pane and reads the latest rows: the terminal outlives its row, and keeps its title, once the agent stops or the tab closes, and `setBase` leaves it on top while the rows change; on another active machine it shows as the gone agent instead (Look › Navigation). Until 015 the app had no agent's screen, and a Home listing every tab with an agent pane opened it; the board took Home's place. The screen fills the window under a bar with a button back, the agent's title and the tab's name with its place, and listens to `terminal-changed`, keeping only the events of its machine and tab, before it calls `terminal_open`; it asks for the cells and lines that fit the space left at the base font (`fit`, once the cell is measured: an estimate would open it twice), and asks again, which restarts the `surface`, only when that size changes, as on a rotation. Leaving it calls `terminal_close`. `Opening` (`src/lib/terminal/opening.ts`) orders these calls: one `terminal_open` at a time, each after the last has answered, only for the latest size asked (the sizes overtaken while waiting are skipped), none once the screen has left, and a `terminal_close` again when it left while one was on its way, as both commands are asynchronous in Tauri and a `terminal_open` answered after the `terminal_close` would leave a `surface` with no screen until the next open, a reconnection or the machine's removal. `terminal_close` names its tab and closes only that one, so the late close of a screen already gone leaves alone a terminal another screen opened in between. Limit: a screen opened again on the same tab within that time, going back and tapping the same row in less than an IPC call, is still closed by it and stays blank until its size changes; telling the two apart would need a token from `terminal_open`. A `closed` event shows "This tab was closed on the Mac" under the last screen, and the screen stays until the user goes back. Rejected: closing the screen on its own when the tab closes, which would hide what the agent last showed.
- **One pane on the phone** (`terminal/shown.rs`): a tab with splits shows a single pane at the Mac's `size`, since `rect` is the phone's and drawing every pane at it would not line up. `Shown` picks, on each line, the pane asked for (the agent's, when the screen was opened from it), else the active one, else the first, so with none asked the phone follows the pane the Mac focuses. Whenever the pane it shows changes, because that pane left the frame or another one became active, it hands every row of the new one as `replaced`; otherwise only that pane's changed rows, numbered from 0 to `size.rows` and never past it, a row the frame did not send going out empty. Each `Update` carries the pane's size, cursor (`None` once cornercase sends `null`) and colours whole, as they are small. Rejected: every pane with its `rect`, which the phone cannot draw at the Mac's width.
- **What goes to the WebView**: `changed_rows` hands over, and forgets, the rows each pane changed since the last call, with `replaced` after a complete frame. A pane's cursor, modes, scroll, colours and whether it is active are not rows: whoever emits reads them from the grid each time, as they are small. After a `NeedRedraw` nothing is emitted until the complete frame: the panes patched before the unknown one hold half a patch.
- **Rows reach the WebView in the contract's own shape**: a run is `text`, `width` and its `style` written with the names of the `surface` JSON (`underline_style`, `{ "index": n }` or `{ "rgb": [r, g, b] }`, cursor shapes in snake_case), and the cursor, size and colours of a pane too, so the TypeScript types generated from them read like upstream's documentation. A run's link stays out: nothing taps a link yet, and repeating a URL on every run of every row sent would cost more than the rest of the run. Rejected: a second set of types for the WebView, written and kept in step by hand.
- **The fixtures** (`crates/core/tests/fixtures/control/surface/v1/frame.json`, `patch.json`) are upstream's, from cornercase-terminal `origin/main` at `7f08441f` (0.13.19); the cases they do not cover are built in the tests.
- **Speed** (2026-11-09, Apple M4, release build, a loaded machine): on a 120×40 pane, a thousand scroll patches (each copying 38 or 39 rows and adding 1 or 2) took about 4 µs a patch to parse from text and 5.5 µs to apply, and a complete frame about 125 µs to parse; all far under the millisecond that would matter. `copy` clones only the rows it reads, not the whole pane as gpui does (8 µs a patch to apply). `WireLines` has its own `Deserialize` (a list is every line, a map the changed rows) rather than `#[serde(untagged)]`, which keeps the whole value aside and reads it again: 5.8 µs a patch and 170 µs a frame with it. The benchmarks are `terminal::grid::tests::bench`, ignored; they run with `cargo test -p cornercase-core --release -- --ignored --nocapture`.

## Typing

Code: `crates/core/src/cli/input.rs` (the events), `src-tauri/src/commands/terminal/input.rs` (the commands), `src/lib/terminal/` (`keys.ts`, `typing.ts`, `Typist.svelte`, `KeyRow.svelte`, `row.ts`, `ctrl.svelte.ts`, `paste.ts`, `sending.ts`, `keyboard.svelte.ts`, `swipe.ts`, `touch.ts`), `src/routes/terminal/Terminal.svelte`.

- **The events are the contract's**: `InputEvent` is `key` (`code`, `mods`, `kind`), `text`, `paste` or `mouse` (`kind`, `button`, `x`, `y`, `mods`), serialized exactly as upstream's `input` reads them (`src/control/terminal.rs` of cornercase-terminal): `mods` left out when empty, `kind` when it is a press, `button` when it is the left one, mouse kinds in kebab case. The key names are upstream's (`term::keys::NAMED`). They reach TypeScript through tauri-specta, so the WebView builds them with the core's own types. `terminal_input(pane, events)` pushes each event on the typist of the active `Store`'s queue (`input --follow --json -`, Connection › The ordered queue) and `terminal_scroll(pane, rows_up)` on its coalesced `scroll`; without a `Store` or a queue both answer `not_connected`. Both are synchronous: they only hand the queue its lines. The queue still takes a JSON `Value`, so the command turns the typed events into one, and the queue's logic did not change. `Sending` (`sending.ts`) sends to the pane the screen shows (`terminal-changed.pane`), nothing once the tab closed or before a pane showed, and turns a refused event or scroll into a toast, without trying again; the typist and the key row are disabled once the tab closed.
- **The pane's modes reach the WebView** (`Update.modes`, `terminal-changed.modes`, `PaneState.modes`), as small as the cursor and sent whole each time, also on a patch that changes the modes and no row: the swipe needs them to choose what to send.
- **The phone keyboard types into a hidden `textarea`** (`Typist.svelte`): 1 px, transparent, without pointer events, at the screen's top left, with `autocapitalize`, `autocorrect` and `autocomplete` off and `spellcheck` false, and a 16 px font, as below that iOS zooms the page on focus (Look › Field); it takes the focus with `preventScroll`. `Typing` (`typing.ts`, no DOM) turns its `beforeinput` into events and cancels it, so the field never keeps what was typed: `insertText` and `insertReplacementText` (a prediction, dictation) become `text`, `insertLineBreak` and `insertParagraph` `enter`, `deleteContentBackward` `backspace`, `insertFromPaste` (the edit menu's Paste) a `paste`. During a composition (an IME) nothing is sent and nothing cancelled; `compositionend` sends its text once. The field always goes back to a sentinel, a single space with the caret after it, so a Backspace on a field that looks empty still has something to delete and still fires. `keydown` takes the keys of a physical keyboard (arrows, Esc, Tab, Enter, Backspace, with Ctrl, Alt and Shift, and `Ctrl` with a character); one with Cmd is left to the system. Enter and Backspace come both as a `keydown` and as a `beforeinput`, so the `beforeinput` that follows a `keydown` of the same key is swallowed and the key goes once. Rejected: `keydown` alone, which carries no text for a prediction, dictation or a composition; reading the field's value after each `input` and diffing it, which keeps the text and guesses at what a replacement replaced; the task's plan B, a visible field that sends a whole line, not needed so far (an IME is still to be checked on an iPhone).
- **A tap focuses it in the `click`** (`src/lib/terminal/Terminal.svelte`): the `pointerup` of a finger that moved less than 10 px only marks a tap, and the `click` that follows calls `focus`, still inside the gesture, so iOS opens its keyboard; a `pointercancel` drops the mark, and a swipe or a pinch is no tap. Found in the simulator (2026-11-09, iOS 27.2): focusing in the `pointerup` gave the field the focus, and the `click` iOS makes up for the same touch then gave it back to the body, so the keyboard never opened. A tap only focuses: it sends no mouse click to a program that reads the mouse (the task's P2). Rejected: a click on the cell as well, which in Claude Code moves things on a touch meant to open the keyboard; clicks wait for a task of their own.
- **The row of keys** (`KeyRow.svelte`, `ROW` in `keys.ts`): `Esc`, `Tab`, `Ctrl`, `↑ ↓ ← →`, `|`, `~`, `/`, `-` and `Paste`, at least 44 px tall (Look), under the terminal at the bottom of the screen, and above the keyboard while it is open. The symbols go as `text`. A key acts on `pointerup`, and its `touchend` is cancelled, which drops the made-up click and with it the change of focus, so the keyboard stays open. Found in the simulator: the planned `pointerdown` with `preventDefault` closed the keyboard on every key all the same, and a touch's `pointerdown` is not a user activation in WebKit, so the clipboard refused Paste (`NotAllowedError`). Limit: on the iPhone Air's 420 pt the row does not fit and `Paste` is cut at its right edge, still tappable.
- **A sticky Ctrl** (`StickyCtrl` in `keys.ts`, `ShownCtrl` in `ctrl.svelte.ts` for the key's look): `Ctrl` stays marked (`aria-pressed`) until the next key, of the row or of the keyboard, which it goes with and is then released; a second tap disarms it. A character with it becomes the key of that character with `ctrl` (`c` → `{"key":{"code":"c","mods":["ctrl"]}}`); a row key gets `ctrl` added; when the keyboard inserts several characters at once (a prediction), only the first takes it and the rest go as `text`. A `paste` goes as it is and still releases it.
- **Paste** (`paste.ts`, the task's P4): `navigator.clipboard.readText()`, on which iOS shows its own Paste callout; a tap on it sends the text as one `paste`, and cornercase brackets it when the program asked for it. An empty clipboard or a refusal is a toast, with nothing sent. Rejected: `tauri-plugin-clipboard-manager`, a dependency the WebView's own API made needless in dev; it comes back only if the release build (`tauri://`) refuses the clipboard.
- **The height with the keyboard** (`keyboard.svelte.ts`): the keyboard is open while `visualViewport.height` is short of `innerHeight` by more than 100 px; then the screen takes the visual viewport's height and its `offsetTop` (iOS lays the keyboard over the page and may scroll it on focus) and drops its bottom safe area, so the row sits on the keyboard. Whenever the scroller's height changes, the grid is scrolled to its bottom, so on a grid taller than the space left its last row sits right above the row of keys. A size `fit` asks while the keyboard is open is dropped (`whileClosed`): the size is measured without the keyboard, so opening or closing it never calls `terminal_open` again nor restarts the `surface`, and the Mac is never resized. Limit: a grid shorter than the space left, as a 50-row pane at the fitted width, stays at the top with a gap under it.
- **The keyboard's accessory bar stays** (the task's P3): WKWebView's ‹ › ✓ bar over the keyboard is part of what `visualViewport` leaves out, so the screen sits above it, and its ✓ closes the keyboard, after which the screen takes the whole height again. Rejected: a Swift plugin that hides it, as Orca does because the bar lifts its page twice, which this screen did not see.
- **Swiping** (`swipe.ts`, `touch.ts`, the task's P1): a finger that moves 10 px or more from where it touched is a swipe for the rest of the touch. Its vertical movement becomes lines at the current zoom (the movement over the line's height), keeping the rest for the next move as gpui's `scroll_rest` does, scrolling naturally: a finger going down brings the history up. A grid taller than the screen, once zoomed, first moves itself in the DOM towards its edge, and the rest scrolls the history. What the lines send follows the pane's modes, as gpui's `wheel_event` and cornercase's `scroll` (which refuses the alternate screen and a program that reads the mouse): to a program that reads the mouse, a `scroll-up` or `scroll-down` per line at the cell under the finger; else on the alternate screen with `alternate_scroll`, an arrow per line; else, off the alternate screen, `scroll` by rows; on the alternate screen without it, nothing.
