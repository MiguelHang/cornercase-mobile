# The connection bar

A topic of [Connection](../connection.md): how the app shows the active machine's connection.

- **Always in sight on `home`** (`src/lib/ui/ConnectionBar.svelte`), hidden on `no-machines`: fixed at the top across the safe area, on `--veil` with the glass blur and a `--border` line under it. Its height is measured and passed on, so `home` and the toasts start under it. A dot in the state's tone (`ToneDot`, which Machines' rows share), one line of text, two when the state has a detail (the error while retrying, the fix when the user has to act), each cut with an ellipsis rather than wrapped, so the bar keeps its height, and at its end the 44 px button to Machines (Look › Navigation). The text and tone come from `status` (`src/lib/connection.ts`), a pure function tested per state. Rejected: a toast per change, since the state lasts and a toast goes. While the phone keyboard covers part of the screen it moves to the top of what is left visible (`top` from `visualViewport.offsetTop`, the terminal's `Keyboard`), since iOS lays the keyboard over the page and lifts it, which took the bar, fixed to the page's top, out of sight above the chat with the keyboard open (041's review). On Android the offset stays 0 and nothing moves. The toasts, fixed under it, still go out of sight while iOS lifts the page; not seen to matter yet.
- **Per state** (Store › States):
  - `connecting`: `Connecting…`, in `--working`. The dot and the cursor of the mark on `home` pulse, in this state only (Look › Touch and motion).
  - `connected`: `<machine> · via <host:port>`, in `--done`. The route is cut to its address, without `ws://`, the path or the token, so the bar never shows the secret; a route that does not parse loses its query. The machine's name comes from `machines_list`; while it has none (the list failed, or has not come back after `Add`), `via <host:port>` alone, with no separator hanging before it.
  - `retrying`: `Retrying in N s`, with the error's message on the second line, in `--failed`. N counts down once a second from when the state arrived, rounded up and never below 1: `in_ms` is fixed in the event, and after a while in the background the local count could pass zero before `connecting` comes. The timer runs only while this state shows, so nothing ticks at rest. The bar is a `status` live region, so the line with the number is hidden from readers and a still `Retrying` is read instead, with the error's line: VoiceOver would read the count again every second.
  - `missing`: `Update cornercase on the Mac`, and `It lacks <names>` under it, with the names the contract lacks, in `--failed`. When a name has the version that brought it (Connection › The contract), the first line ends `to 0.13.78 or later`, the newest of them when several do, so the user knows which release to install rather than only what is missing.
  - `not_paired` (058): `This Mac no longer recognizes this phone`, and `Scan its code again in Machines` under it, in `--failed`, for a `403` on cornercase's `/cli` (Store › States). It speaks of the Mac and not of a token: the user forgot the phone in cornercase › Settings › Remote › Phone app, or with `config remove app.<id>`, and only a new code from there pairs it again. A machine with no secret on any route, or with no routes, reads the same (Store › States): a new code is its fix too. The bar offers no button, since `home` has no form: in Machines, the active machine's row reads `Not paired` (a machine that is not active and has no secret reads `No secret` from its probe, with `Scan again` beside it) and offers `Scan again`, which opens that machine with its form for the code open; the code pairs, then merges into that machine and replaces its secret (Machines › The same machine). Before 059 a `401` of the bridge had a state and a text of its own, `unauthorized`; `/cli` answers `403` instead, so it went (Connection › Errors told apart).
  - `incompatible`: `Incompatible with cornercase on the Mac`, and its message under it, in `--failed`.
  - **What happened first, what to do second** (review of 2026-11-15): until then `missing`, `not_paired` and `incompatible` were one line each, and at 390 pt the fix was cut off, the one part the user needed. Splitting them as `retrying` already was keeps the bar's height for every other state and shows the whole fix. Rejected: wrapping one line, which makes the bar's height follow the text's length.
  - `offline` (028): `No network`, in `--failed`, with no pulse and no countdown: the store waits for the network rather than retrying.
  - `none` reads `Not connected`, though `home` does not show it: the route goes back to `no-machines`, or, with other machines left, Machines stays open without a connection.
- **Checked on 2026-11-09** in the iPhone 17 simulator, iOS 27.2, against `cargo run -p cornercase-bridge` on the LAN and cornercase 0.13.19:
  - after `Add`, `Connecting…` for under half a second, then `MacBook · via 192.168.1.20:8765` and the pane count;
  - with the bridge stopped by `SIGSTOP`, a relaunch stayed in `connecting`, the dot and the cursor pulsing (their colours, read in screenshots, rose and fell), then went to `Retrying in 1 s` with `the bridge did not answer in time`;
  - with the bridge killed, `Retrying in N s` with `cannot reach the bridge: Connection refused (os error 61)` under it, counting down a second at a time, the wait growing between attempts (2, 8, 15 s), and no toast; started again on the same port, the app reconnected on its own.
