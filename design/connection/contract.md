# The contract

A topic of [Connection](../connection.md) (`crates/core/src/cli/contract.rs`, `cli/contract/`): what the app needs from the machine's cornercase is checked against the `contract --json` that `pick_route` already brings back, never against a minimum cornercase version, so a build of upstream `main` works and what is missing is named.

- **Reading it**: `Descriptor` (`from_value` for `pick_route`'s JSON, `FromStr` for text) takes `version`, `contract`, `boot`, `operations` (`name`, `available`, `reason`), `features` and `streams` (`name`, `version`). A key that is absent takes its default and a key it does not know is ignored, so what upstream adds breaks nothing. A value of the wrong shape is `Json`, which names the kind of mistake, its line and column, never the text (`transport::json_error`, shared rather than copied).
- **The contract number**: the app knows `CONTRACT = 1`. A higher number is `ContractTooNew { server, app }`, which says to update the app: the old side is the app, and cornercase raises the number only for a change that breaks clients. `contract = 0`, which is also what an absent key reads as, is `Outdated`: every server that has `contract` sends 1 (since cornercase-terminal#283), so a descriptor without it is not one to trust.
- **`REQUIRED`**: three typed lists, every name checked against cornercase 0.13.78 (`Command::NAMES`, `FEATURES`, `describe`), each entry for the task that uses it.
  - 30 operations: `status`, `watch`, `app`, `events` (012, 015: `status --json`, `status --follow`, `status --app --follow`, `events`); `last-message`, `send` (016: `read --last-message`, `send`); `keys` (017); `mark` (044: `mark --reviewed`); `paste-file` (018: `paste-file -`); `view`, `surface`, `redraw` (019, 020: `surface --patches`); `input`, `scroll` (021); `view-set` (022: `--claim`, `--inactive`); `start` (023, 024; `new-workspace` left the start screen in 045); `account-list` (023: `account list --check`, the installed agents, Starting work); `issue-sources`, `issue-list`, `issue-read` (024: `issue sources`, `list`, `read`); `changes`, `changes-file`, `changes-viewed` (025); `files-list`, `files-read`, `files-search` (026); `flow-list`, `flow-run` (047: `flow list --project`, `flow run --issue`, Starting work › With a flow); `close-agent` (056: `close --agent --check`, then `close --agent`); `app-routes` (058: `config pair app --routes --json`, Machines › Routes learned).
  - 12 features: `boot` (010, 012: `boot` and `stale-boot`); `notices` (012: the CLI refuses `events --notices` without it); `views`, `surface-patches` (019 to 022: the CLI refuses `--view` and `--patches` without them); `machine-start` (023: the CLI refuses `start --placed` without it); `issues` (024: `start --issue`); `changes`, `files` (025, 026: the shape of their answers); `accounts`, `account-switch` (052: `--account` on `start` and `flow run`, and `active`, `label` and `system_label` in `account list`, Starting work › Where the choices come from). Those two came in 0.12.154 and 0.12.159, before `files-search` (0.12.215), which is already required, so they turn away no server the app accepted, and the account pickers need no check of their own at run time. `close-agent-tabs` (056: the CLI refuses `close --agent` without it, and it promises that `close-agent` stops agents and removes nothing from disk). `close-agent` came in 0.12.167 and `close-agent-tabs` in 0.12.178, both before `files-search` (0.12.215), so neither turns away a server the app accepted, and closing an agent needs no check of its own at run time. `cli-endpoint` (058: the server serves `/cli`). 058 asked it of the bridge's routes too (P3), so a machine whose cornercase was older than 0.13.78 was asked to update even behind the bridge, and 059 removed the bridge without turning anyone away.
  - 7 streams, each at version 1: `events`, `watch`, `app`, `surface`, `view`, `changes`, `files`. Another version changes the lines that 012, 019, 025 and 026 parse, so a stream that is absent or at another version counts as missing.
  - Left out: `requests --follow` and `input --follow` (011's queue), subcommands of the CLI rather than operations of the socket, so the contract has no name for them (Upstream gaps); 011 falls back to single commands when they do not start. `update-check` and `update-install`, which a dev build of cornercase marks unavailable.
- **The version that brings a name** (`Missing::since`, 058): `cli-endpoint` and `app-routes` came in 0.13.78, so the bar says to update cornercase to it (The connection bar). The version is tied to the name, never read from `--version` (D5): it only words the advice. The names required before 058 have none.
- **`missing(descriptor)`** lists what the server lacks, operations then features then streams, each in `REQUIRED`'s order, with its `Kind` and, for an operation the server has but marks unavailable, the server's `reason`. All or nothing for now: 012 stops on any `Missing`, so a server without `files` blocks the whole app though only 026 needs it. `Missing` already names the entry, so degrading screen by screen later is additive.
- **An old cornercase**: a server without `contract` answers `` has no `contract` command ``, and an older CLI refuses it with clap's `unrecognized subcommand 'contract'`. `outdated` turns a `Failed` whose stderr holds either into `Outdated`, which says to update cornercase on the machine and restart its server. They are matched as substrings, since the CLI prints the server's text after anyhow's prefix (upstream's own tests do the same), and the text is what tells them apart from any other exit 2, such as `/cli` refusing an argv, which shares clap's code. Servers older than the JSON requests stay a plain `Failed`.
- **A CLI and a server of different versions**: `contract` speaks for the server, but the installed CLI parses the flags (`--placed`, `--patches`, `--follow`). An old CLI with a new server fails in that command, with clap's exit 2 and `unexpected argument`, not here. Documented, not solved.
- **The boot** (`cli/contract/boot.rs`): `Descriptor::boot` gives the server's `Boot` (its pid and start time, not a secret). `BootWatch::observe` says `Same` for the first boot it sees and while it does not change, and `Restarted` once when it changes, for the `Store` to forget the old server's session and move the queue (Store). The boot is the server's, not the route's: the same machine reached by another route gives the same boot.
- **`stale-boot` is exit 4**: a command given a `--boot` that is no longer the server's fails with 4, and `transport::json` maps it to `StaleBoot` with the stderr. Only `stale-boot` uses 4 today (3 is a partial result, 2 a usage error, 126 and 127 come only with `--remote`, which `/cli` refuses); if upstream ever reuses 4, this mapping would lie.
- **The fixtures** (`crates/core/tests/fixtures/contract/`): `0.13.78.json` is `contract --json` from the published cornercase 0.13.78 (upstream `e994b1cb`), run on an isolated server (138 operations, all available, 71 features, 11 streams); `no-operations.json` is the same without `operations`; `0.13.19.json`, from cornercase 0.13.19 (124 operations, 42 features, 10 streams), stays as a server from before `/cli`, for the test that names what it lacks and the version that brings it. The tests of `contract.rs` and of `boot.rs` read them through `cli/contract/fixtures.rs`, a module only the tests build, so no test module imports another.
- Rejected: a minimum version read from `--version`, like cornercase-gpui (a version cannot name what is missing, nor tell what a build of upstream `main` has); one list of names without kinds (an operation and a feature or a stream share names, such as `changes`, `files` and `events`, and a stream needs its version).
