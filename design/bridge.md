# Bridge

History. The development bridge was a binary in `bridge/` that ran on the Mac from task 003 to 059: a WebSocket server that ran `cornercase <argv>` per connection. Its purpose was to fix the format cornercase-terminal would serve as `/cli`, and it did: since 058 the app talks to cornercase's own `/cli` (cornercase 0.13.78, upstream #838 and #851), and 059 removed the bridge with its routes and everything that existed only for it. What the app keeps from it is the protocol (`crates/core/src/protocol.rs`), the machine code's format (`crates/core/src/machines/code.rs`) and the guards that 059 left behind (Retired in 059, below).

- **Why it was built**: the app has neither the cornercase binary nor ssh, and cornercase served nothing a phone could use: browser access serves the window's own protocol to a web page, through Tailscale only. With a bridge of our own the app and its protocol could be built and tried before asking upstream for anything.
- **What it was**:
  - one WebSocket connection per command, so streams (`status --follow`, `surface --patches`, `events`) and one-shot commands shared one shape and one lifetime;
  - the protocol, one JSON object per text message with exactly one key: `argv` first and once, then `stdin`, `stdin_base64` and `eof` in; `stdout`, `stderr` and one last `exit` out;
  - one way to refuse, a `stderr` line and `{"exit": 2}`;
  - an allowlist of the commands that may run;
  - the command in a process group of its own, ended with `SIGTERM` and then `SIGKILL` 2 s later;
  - lines of 16 MiB and messages of 1 MiB at most, backpressure end to end, a Ping every 15 s and 45 s of silence before cutting, 1001 on stopping;
  - listeners only on the Mac's LAN and Tailscale addresses, on one port (8765);
  - a token of 32 random bytes in the URL's query, kept `0600` in `~/.config/cornercase-bridge/token`;
  - from 035, one machine code per Mac with every address, and `--bridge-routes` (The machine code, below).
- **What went upstream** (057, upstream's `design/phone-app.md`): the protocol byte for byte, one connection per command, the process group, the limits and the backpressure, the ping every 15 s and the 45 s of silence, 1001 on stopping, listening only on the LAN's and Tailscale's ranges, the machine code's format (with `code=` in place of `token=`) and `--bridge-routes`, as `config pair app --routes --json`.
- **What changed on the way**:
  - a secret per device, traded for a single-use code and sent in a header, rather than one fixed token in the URL;
  - what may run computed from cornercase's own `reach::kind`. The bridge wrote its allowlist out by hand from upstream's `Kind::There`, so that a new command stayed refused until someone added it; upstream owns both sides and keeps one boundary for `/cli` and `requests --follow -`;
  - the interfaces read every 2 s rather than once, so a network that comes no longer needs a restart;
  - its own port, 47682, behind a switch in Settings › Remote › Phone app that is off by default.
- **Decisions the app still lives by**:
  - **Ping as a control frame**: an empty WebSocket Ping, with anything heard from the client counting as alive, rather than upstream's `{"type":"ping"}` of browser access. A page's JavaScript can neither send nor see a Ping, but tungstenite answers one on its own, and a message would have been a new kind on both sides of a strict protocol. The cost: a client answers only while it reads, so one that stops reading for 45 s is cut, which is wanted, since it holds a command and its output (Connection › Ping and backpressure).
  - **Bytes as `stdin_base64` text**: rejected were binary frames, two message shapes for a 33 % saving on rare images, and a command of the bridge that stored the image on the Mac, which would have left the argv ↔ cornercase contract.
  - **Strict parsing**: an unknown key, two keys, a wrong type or `{"eof": false}` is refused rather than guessed at, so a typo never runs a command with empty input; a refusal never echoes the message.
  - **Types in the core**: the protocol lived in `crates/core` from the start, so the bridge and the app's transport could not drift apart. That is how `/cli` came to share it byte for byte.
- **The machine code** (035): one code and one QR code per Mac, with every address it listens on, so adding a Mac adds one machine and not one per network. Before 035 the bridge printed a code per listener, and the LAN's and Tailscale's became two machines unless the app's offer joined them (027).
  - **Its format**: `ws://<first>:<port>/?token=<token>&also=<host>&also=<host>&name=<name>`, the first address in the authority (IPv6 in brackets) and the others in `also=`, bare. They share one port, so `also=` needs none. `name=` is the Mac's name (`scutil --get ComputerName`, the one the user recognises), percent-encoded and cut to 64 characters. cornercase shows the same format with `code=` (Connection › Machines › Pairing with cornercase's code).
  - **Why a `ws://` URL with `also=` and `name=`**: it was compatible both ways. An older app read it as a URL of one route and ignored the parameters it did not know, while the new one took a URL of one route as a code without a name. Rejected: a scheme of our own, `cornercase://machine?…`, cleaner and good for a deep link, but an older app refused it; JSON in the QR code, bigger, refused by an older app too, and no URL to paste.
  - **Its size**: at error correction level L, LAN and Tailscale's IPv4 with a 21-character name made 127 characters and 49 × 25 modules; three addresses, port 65535 and a 64-character name made 65 × 33, within 80 columns (measured on 2026-11-09 with `qrcode` 0.14.1). Upstream quotes these numbers.
  - **`--bridge-routes`**: an argv the bridge answered itself, after the token, with `{"routes":[{"host","port"}]}`, so the app could add the addresses the Mac gained after the code was scanned. An argv rather than a new message changed neither the protocol nor the `Transport` trait; also rejected was a header in the handshake's `101`. Upstream took it as `config pair app --routes --json` (Connection › Machines › Routes learned from the Mac).
- **Rejected or left out along the way**: TLS and pairing (development only, the token was the boundary); a limit per peer on handshakes; watching the interfaces; an address of the user's choice to listen on (`--listen`, task 005's), a way around the LAN and Tailscale filter; `0.0.0.0`, which would have faced the internet with a token in clear.
- **Retired in 059**. The bridge duplicated what `/cli` serves, kept a second credential alive (a fixed token in the URL beside the device's secret) and tied the core's tests to it through a dev-dependency cycle. What went with it: `bridge/`, the `bridge` kind of route, codes with `token=`, matching a saved machine by its token, the `401` and `Error::Unauthorized`, and `--bridge-routes`. What stays:
  - a `machines.json` with bridge routes still loads; they and their secrets are dropped, and a machine left without routes is forgotten (Connection › A file with bridge routes still loads);
  - a code of the bridge, pasted or scanned, is refused with a message that says where to find cornercase's (Connection › Machines › A code of the old bridge is refused);
  - the transport's tests run against a fake `/cli` rather than the bridge (Connection › Tests against a fake `/cli`).
  - The notes "Checked … against the bridge" in other files, and tasks 003 to 006, 033 and 035, are dated history and stay as written.
