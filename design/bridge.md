# Bridge

A development-only binary in `bridge/` that runs on the Mac. Its purpose is to fix the format that cornercase-terminal will later serve as `/cli` in `src/web/`.

- **WebSocket ↔ `cornercase <args>`**, one WebSocket connection per command, so streams (`status --follow`, `surface --patches`, `events`) and one-shot commands share one shape and one lifetime.
- **Protocol**, one JSON object per message:
  - client → `{"argv": [...]}`, the first message, required;
  - client → `{"stdin": "<line>"}`; bridge → `{"stdout": "<line>"}` and `{"stderr": "<line>"}`, line by line;
  - bridge → `{"exit": n}`, then it closes.
  - client → `{"stdin_base64": "…"}` for bytes and `{"eof": true}` to close stdin: `paste-file -` sends image bytes, and `send -` and `paste-file -` read until end of input. Rejected: binary WebSocket frames (two message shapes in the protocol for a 33 % saving on rare images) and a bridge command that stores the image on the Mac (it leaves the argv ↔ cornercase contract).
  - `stderr` was added to the first draft so the app can show the CLI's errors.
  - **Strict parsing**: a message is one JSON object with exactly one of the keys above. Invalid JSON, a value that is not an object, an empty object, an unknown key, two keys (`{"stdin": "a", "eof": true}`), a wrong type, `{"eof": false}` and a `stdin_base64` that is not standard base64 (padded, `+` and `/`) are refused rather than guessed at, as upstream's `requests` refuses unknown keys: a typo must not run a command with empty input.
  - **Order**: `argv` comes first and once. A first message of another kind and a second `argv` are refused; after `argv` only `stdin`, `stdin_base64` and `eof` are read.
  - **One way to refuse**: a protocol error and a refused argv both become one `stderr` line and `{"exit": 2}`, the status of upstream's `Error::WrongUsage`, so the WebSocket side (task 005) has one path for both. The line is in English, in the style of upstream's usage errors, and is one line: control characters become spaces (`Refusal::new`). A refused argv echoes no more than its first word (or `plugin` and its action), cut after 80 characters, so no path or id of the arguments lands in it. A protocol error echoes nothing of the message: serde's error, which quotes the value or the key it choked on, becomes one generic reason by its category (not one JSON object with one key, cut short, or not a known key with a value of its type), and a bad `stdin_base64` says only that; telling which key or type was wrong is left to the developer reading the protocol.
  - **Where the types live**: `crates/core/src/protocol.rs`, and `bridge/` depends on `cornercase-core`. The app's transport (task 007, in `crates/core`) speaks the same messages; keeping them in `bridge/` would have meant copying them there (jscpd) or making the app depend on a development tool. The allowlist stays in `bridge/src/allowlist.rs`: only the bridge decides what runs on the Mac.
- **Allowlist**: an argv runs only if `allowed` accepts it; a refused argv gets a `stderr` line and `{"exit": 2}`, and nothing runs. The list is copied from upstream cornercase-terminal 0.13.19 (`origin/main` @ `7f08441f`, 2026-11-07), and is checked again by hand when upstream changes.
  - **Allowed**, compared exactly and case-sensitively (clap infers neither subcommands nor long options upstream, so `stat` and `--rem` are not aliases):
    - the 60 control subcommands of upstream's `Control` (`src/cli/args.rs`, clap's kebab-case names, none renamed or aliased): `status`, `open`, `clone`, `new-workspace`, `new-tab`, `split`, `setup`, `start`, `send`, `keys`, `held`, `read`, `wait`, `close`, `rename`, `focus`, `go`, `notify`, `away`, `mark`, `search`, `todo`, `queue`, `events`, `flow`, `contract`, `surface`, `view`, `view-set`, `input`, `requests`, `scroll`, `selection`, `resize`, `redraw`, `ratio`, `link`, `paste-file`, `theme`, `config`, `move`, `move-pane`, `collapse`, `expand`, `group`, `issue`, `changes`, `files`, `usage`, `ports`, `pull-request`, `context`, `recap`, `processes`, `worktrees`, `machines`, `tour`, `agents`, `account`, `profile`, each with whatever follows it (`config set` and `worktrees remove` included: sub-subcommands are not filtered);
    - `stats`;
    - `plugin` followed by one of the actions whose `asks_the_server()` is true: `actions`, `status`, `run`, `popup-close`;
    - `--help`, `-h`, `--version` and `-V`, alone: clap answers them without the server, which serves to try the bridge with `websocat` and to read the Mac's version. With anything after them they are refused: knowing what `--help status` or `--version start-server` would do means parsing like clap, and the rule is meant to need no parsing.
  - **Refused**, everything else: no argument (it opens the window, which needs a TTY), `start-server` (it changes the Mac's server), `kill-server`, `update`, `restart`, `logs`, `remote`, `skill`, `server`, `proxy`, clap's implicit `help`, any unknown name or other case (`Status`), `plugin` alone, `plugin windows`, the `plugin` actions that act on this machine (`link`, `install`, `update`, `remove`, `unlink`, `list`, `enable`, `disable`, `logs`), any other word or an option after `plugin`, and any other first argument that starts with `-`.
  - **Why explicit**: it is upstream's `Kind::There` of `src/cli/reach.rs` (what `--remote` sends to the server) minus the window and `start-server`, written out rather than computed as "everything but the excluded". The list is the bridge's boundary and must not grow by itself: a command upstream adds stays refused until it is added here by hand. A command upstream renames breaks without a warning; task 010 (`contract` at boot) is where that shows, not this list. Rejected: "everything but `Kind::Run`, `Kind::Here`, `Kind::Apart`, `plugin windows` and the window", which lets a new command through unseen.
  - **Out though upstream calls them `There`**: the window (no subcommand) and `start-server`. The rest of what is out is what upstream itself keeps local: `Kind::Run` (`update`, `restart`, `kill-server`, `logs`, processes of their own), `Kind::Here` (the local `plugin` actions), `Kind::BesideTheWindow` (`plugin windows`), `Kind::Apart` (`remote`, `skill`, `server`, `proxy`), and `help`.
  - **`--remote` anywhere**: an element equal to `--remote` or `--remote-command`, or starting with `--remote=` or `--remote-command=`, is refused in any position, after `--` or as another option's value too, and before the subcommand is looked at, so the message names `--remote`. The bridge runs commands on this Mac; reaching another machine over ssh from the phone through it is out. The false refusals are accepted (`new-tab -- echo --remote`, `clone --file --remote`), while an element that only contains the text (`"say --remote"`) passes. `CORNERCASE_REMOTE` in the bridge's environment means the same and is removed when the process starts (task 004); the list does not see the environment.
  - **`--machine` is allowed** (`stats`, `usage`, and the commands with upstream's `MachineArg`, such as `start`): it is `Kind::There` upstream. `--remote` is refused so that the bridge's process opens no ssh; the Mac's server does reach other machines, through `machines` and `--machine`, and whoever holds the token can add them (`machines add <name> <destination>`) and then reach them: that is the owner's power, like `config`.
  - **`requests --follow -` is allowed**: its lines are filtered by the Mac's cornercase, which runs only the `Kind::There` commands on a line and answers status 2 for the rest: `--remote` and `--remote-command`, no command, `start-server`, `update`, `restart`, `kill-server`, `logs`, `remote`, `skill`, `server`, `proxy`, the local `plugin` actions and `plugin windows` (#558, #674), streams included (they need a connection of their own). That holds since `requests` exists, 0.12.234, whose filter already went through `reach::kind`; `plugin windows` came in 0.13.15, so an older cornercase has no such command to run. On a cornercase older than 0.12.234, `requests` is an unknown subcommand and clap refuses it with status 2.
  - **What it does not protect**: the Mac from its owner. `new-tab -- <cmd>`, `send` to a shell, `config` (`agent_commands`) or `worktrees remove` run or delete whatever they are told. `machines add` (or `edit`) points the Mac's server at any ssh destination, which `--machine` then reaches, and `machines update` installs a release there. The boundary is the token (task 005); the list keeps the bridge from breaking the Mac's server and window, and its own process from opening ssh.
- **Disconnects kill the process** and its group.
- **Auth**: a fixed token in the URL (`?token=`), checked before the upgrade. No TLS and no pairing: development only.
- **Listening**: only on LAN or Tailscale interfaces, never `0.0.0.0` or a public address. On start it prints a QR code and the `ws://<ip>:<port>/?token=…` URL of each interface.
- **Proposal for upstream**: the last task documents this format as a proposal for `/cli` in cornercase-terminal.
