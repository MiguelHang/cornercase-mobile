# Where the choices come from

A topic of [Starting work](../starting-work.md): the session's workspaces and which one is chosen, cornercase's agents and their accounts loading apart, which account and which agent are chosen, every account to pick, servers without `--account`, the model as free text, a server restart.

- **The workspaces are the session's**, as the `Store` last read them (`start_projects`, `StartChoices { boot, projects }` with `ProjectChoice { id, name, workspaces }` and `WorkspaceChoice { id, name }`): the names the Mac shows (`custom_name`, else `name`, for both), in the session's order. No call of its own, so they show at once. The picker lists them flat as `<project> › <workspace>`, the label the board's rows and upstream's places use; with none, it says `No workspace is open on this Mac.` and `Start` rests.
- **Which workspace is chosen** (045): opened from an agent, that agent's (Starting work › Starting from an agent), while the session has it; else the last one an agent was started in from the app while it runs, if the session still has it on the same `boot`; else the only one; else none, and sending says `Choose a workspace` under the field. The same memory as the agent's, so nothing is kept after the app closes. The id is kept with the `boot` it was read on, and taken only while the `Store` gives that boot: upstream gives pane, tab and workspace ids again from 1 on every start, `restart` and updates included, so after one the same id may name another workspace, and `start` takes no `--boot` to refuse it. Rejected: the id alone, which "while the session has it" lets through when the new run gives it to another workspace (review of 2026-11-10); and matching the workspace by its label across boots, which two workspaces of the same name defeat.
- **The agents are cornercase's**: `account list --check --json` through the queue (`installed_agents`), its `agents` field, only those with `installed: true`, in cornercase's order. The app keeps no list of agents, so one cornercase adds shows up without a release of the app. An absent `agents` (a server with `account-list` but older than cornercase-terminal#543) reads as none installed. Its `providers` give the accounts (below); the paths and `profiles` are not read.
- **They load apart**: `account list --check` runs each account's status command when accounts were added (up to 20 s each, upstream's `design/accounts-and-profiles.md`), so the projects and the other fields can be filled while the agents load. The agents' picker says it is reading, shows cornercase's reason with `Try again` when it fails, and says when none is installed, which holds `Start`.
- **The accounts come in the same answer** (task 052): of `providers`, each `provider` (the agent), its `accounts` (`name`, `label`, `login.state`), `system_label` and `active`, read leniently, so an answer without `providers`, `label`, `system_label` or `login`, or with `null` in one of them or in `active` or `system_login`, reads as no accounts or empty values, not as an error. `installed_agents` gives `StartAgents { agents, accounts }`: per agent with at least one added account, its options, its own login first (`name` empty, labelled `system_label`, else `System`) and then each account in cornercase's order (its `label`, else its `name`), each with its login (`signed-in`, `signed-out`, `failed`, or `unknown` when absent), and its default. An agent without added accounts has no entry and no picker: its own login is all it has. No call of its own, so the accounts load, fail and are read again with the agents (They load apart): while the agents are read, or after their read failed, no account picker shows, and `Try again` brings both. Rejected: `profile list`, a second call for what the phone does not offer (Starting work › Left out).
- **Which account is chosen**: the agent's default, `active`, the account cornercase's selection gives it when the command says nothing (a profile in use is already in it); empty, the own login, when `active` is absent or names no account of the list, as upstream reads it. Upstream picks `--account`, then `--profile`, then the calling pane's accounts, then that selection; the bridge drops `CORNERCASE_PANE` (Bridge), so from the phone `active` is the account that applies. Should the bridge ever let a pane through, the default shown would not be the real one. The choice is kept per agent (`StartAccounts`, a `SvelteMap`) while the form lives: going to another agent and back gives it back, and the issue's `Agent` and `Flow` share it. A new boot empties it, with the agents read again. Rejected: remembering the last account used across forms, as spending the wrong account is worse than one more tap, and the Mac's dialogs preselect the default each time too.
- **Every account can be chosen** (P2 of 052), its state in its option: `<label>` when signed in or `unknown` (Gemini has no status command), `<label> · signed out`, `<label> · could not check`. With a signed-out account chosen, a note under the picker says `This account is signed out: the agent will ask to log in on the Mac.` Upstream starts an agent with an account without a session, which asks to log in in its pane (seen from the phone in `Terminal`), and `failed` may be the check's own limit of 20 s. Rejected: greying them out, which would refuse what cornercase allows.
- **Servers without `--account`**: `accounts` (0.12.154, `--account` and `--profile` on `start` and `flow run`) and `account-switch` (0.12.159, `active`, `label` and `system_label`) are in `contract::REQUIRED` (Connection › The contract). `files-search` (0.12.215) is required already, so no server the app accepted before is turned away, and the form needs no check of its own at run time, nor a line in Upstream gaps.
- **Which agent is chosen**: the first installed one (claude comes first in cornercase's order), then the last one started from the app while it runs, if it is still installed. Rejected: the `agent` of `config --json`, another call with a large answer, useless when it is `auto`; and no default, one more tap almost every time.
- **The model is free text**, optional: cornercase says nothing of the models each agent takes (Upstream gaps), and a list in the app would go stale.
- **After a server restart** (a new `boot` while the screen is open) the choices are read again, since ids belong to one run of the server and `start` takes no `--boot`. The chosen workspace is emptied even when its id is still there, as that id may now name another workspace, and gives way to the only one, else to none (the last used is of the old boot); an issue's chosen place is emptied too, its ids being of the old boot as well. The places of an issue's form come with the issue, of the old boot as well, so after a restart its `Where` lists none and says `cornercase restarted: go back to the issue to see where it can start.`, and `Start` sends nothing: going back to the issue and `Start` again gives them anew. Rejected: reading the places again from the form, one more call for a rare case, and keeping them, as an id of the old boot may now name another workspace or project (ids of every level come from one counter). Every other field stays. The boot is the `Store`'s, given with the projects: every restart makes the `Store` connect again, so each time the connection comes back to `connected` the screen reads the projects (the session, no call to the Mac) and, when their boot changed or the last read of the agents failed (such as one cut off by the dropped connection), the agents. Rejected: the boot of the board's rows, which is missing while no agent runs, the usual case before the first one starts; and reading the agents again on every return to `connected` after a read that worked, which comes with every return to the foreground and runs `account list --check` for nothing.
