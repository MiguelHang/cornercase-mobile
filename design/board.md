# Board

The active machine's screen, under the connection bar: every agent of its projects with its status and how long it has been in it, the agents they started folded under them, the ones that need the user first, live. Follows cornercase-gpui's agents section (`design/session-model.md`: loudest status, `status_rank`, `agent_title`; `src/model.rs`, `src/sidebar/agents.rs`), read on `main` on 2026-11-09.

## Rows

- **One row per pane with an agent** (`crates/core/src/board.rs`, `AgentRow`), from every project of the session; a pane without one gives none. The rows are built in the core, beside the session and the record of since when (below), and only they reach the WebView, over `agents` and `agents-changed` (`design/architecture.md` › Commands and events). Rejected: grouping and sorting the session in TypeScript after a `session-changed`, which sent the whole snapshot over IPC about every 500 ms while an agent worked and left the order untested against upstream's fixtures.
- **A tree: each agent under the agent that started it** (Tree and folding). Until 038 the board was flat, one row per pane, leaving gpui's tree (`agent_rows`) out until a real list was too long. A capture of the user's iPhone on 2026-11-09 showed what that cost: a flow's team and the agents an agent started with `start` or `split` filled the board as loose rows while they worked or once done, burying the ones the user had started. The row carries the listed `parent`, its `depth` and its `role` from the core, and `rank_status`, the status its branch sorts and is sectioned by (Order).
- **Names as the Mac shows them**: a project's, workspace's and tab's `custom_name`, else its `name`. The row carries `workspace_count` rather than a place already written, so the UI writes the line as gpui's `place` does: the project alone when it has one workspace, else `project › workspace`. `tab_name` goes out too, for the chat's header (Chat › The screen) and the agent's terminal, under its title. The row also carries the session's `boot`, the same on every row, and its `tab` and `pane`, all the agent's terminal needs to open the pane and remember its zoom (Terminal › The grid › Opening it). Rejected: `boot` beside the rows in `agents-changed`, a second field for the forwarder to compare and the UI to keep, for a value that only matters with a row.
- **The title is gpui's `agent_title`**: the pane's `title` without the characters before its first letter or digit (a spinner frame, `✳`), trimmed; an empty or missing one is `null`, and the UI shows the agent's name (`claude`) instead.

## Order

- **By branch, each by its loudest waiting**: roots and, inside each parent, siblings follow the rule below, but with the branch's own rank, the highest of the agent's and of its descendants' that are `waiting` or `failed` (`crates/core/src/board/tree.rs`), and the `since` of the one that raised it. A child that waits lifts its whole branch to the top, so an agent that needs the user never sits low on the board, hidden in the branch of an agent that works. A child that is `done` or `pending` does not: a coder finishing would otherwise send a whole team to Done while its orchestrator still works, and a folded row already says it (Tree and folding). Siblings follow the same rule rather than the session's order, as upstream does, so what waits is on top once unfolded too. Then the branch is written in preorder, every child right under its parent. Rejected: upstream's sidebar order, a tree whose rows never move by status: on a phone the board is read, not clicked through on a desk, and the 015 rule of what needs the user first still holds.
- **By status, then by time in it.** The rank is gpui's `status_rank`: `waiting` > `failed` > `done` > `pending` > `working` > `idle`, and a status the app does not know ranks as idle, so one upstream adds sorts last rather than failing.
  - **`done` above `pending`, as gpui, not as the TUI** (`activity::Status`, which puts `pending` first, since it is the user's own mark). gpui is the reference client, and on a phone a finished turn not seen yet is the news, while `pending` is a reminder the user set by hand that may stay for days.
  - **`shell` ranks with `working`**, unlike gpui's `status_rank`, which leaves it with idle: the agent wakes up when its background command ends, which is why the TUI and Claude Code's own agents view count it as working.
- **Within a rank, the longest in its status first**, with an unknown `since` before any known one: such an agent was already in that status when the app connected, so it has been there longer than any time the app saw. The times are compared as text: upstream writes them in UTC with milliseconds and a fixed width, so the text order is the time order, and the core needs no date library. Ties keep the session's order (project, workspace, tab, pane), since the sort is stable.

## Sections

- **A branch goes whole in its root's section**, the section of its `rank_status`: a child that works under a root in Waiting is drawn in Waiting, under its parent, rather than in Working away from it. A root that works with a waiting child shows in Waiting with its own working dot; the child below, or the folded row's attention, says why.
- **Waiting** (`waiting`, `failed`), **Done** (`done`, `pending`), **Working** (`working`, `shell`) and **Idle** (`idle`, no status, an unknown one), in that order; an empty one is not drawn. They cut the rank in four, so the rows' order inside each is the core's (`src/lib/board.ts`). The names are in English, like the rest of the UI; the task's were Spanish.
- **Idle has its own section, last.** Rejected: idle inside Done, which dilutes "what finished and you have not seen", and hiding it, since an idle agent is still someone to write to from the phone.

## Tree and folding

- **The parent is the pane's `parent` only when it is listed**, a pane of the snapshot with an agent; otherwise the row is a root. A `parent` naming the pane itself counts as none. With A → B → C and B closed, C is a root and does not climb to A, as upstream. A child in another project or workspace (`start --worktree`) still hangs from its parent and keeps its own place on its second line.
- **Cycles cannot hang the walk or lose a row**: the tree is walked from the roots with a visited mark, then every row not reached is taken as a root, the algorithm of upstream's `agents::tree::order` and gpui's `src/model/tree.rs`. Only a session edited by hand has one.
- **Indented by level, three at most** (`--inset-wide` a level): deeper rows draw at the third, since a phone has no width for more and real teams are one or two levels deep. No `├`/`└` guides: the indent reads on a phone and the guides would need their own column.
- **An agent with children comes out folded, with a triangle under its dot** (051): the dot's column holds the row's `StatusDot` and, under it, a filled triangle of the same 14 px in `--soft`, its corners a little rounded, pointing right and turned 90° once unfolded over `ENTER_MS`, at once with Reduce Motion (Look › Touch and motion). Both are one button of its own, laid over the dot's column, with `aria-expanded`, named `Show 3 subagents` folded and `Hide 3 subagents` unfolded (`disclosureName`; every level, as `+n`), so folding never opens the chat, and a tap on the rest of the row opens it. Folding hides the descendants of every level; a child born under a folded parent stays hidden and only raises `+n`. Folded by default because the point is that the team does not fill the board; one tap shows it.
  - **The target is 44 pt wide over the dot**, as tall as the row (at least 44), centred on the dot's axis and moved with the indent: its left edge is the dot's (`--inset` into the row) plus half the dot, 7, minus half the target, 22, hence the `- 15px`. It lies over the row's button, before it in the page, so VoiceOver reads `Show 3 subagents` and then the row. The dot and the triangle are centred as one block in it, 6 px apart.
  - **The agent's status stays on its row for VoiceOver**: the button's name covers the dot inside it, which is hidden from VoiceOver so it is not read twice, and the row's own column, empty to the eye, carries the status as `.spoken` text (Look › Touch and motion), so the row still reads `Waiting, Lead, repo, 3 min`.
  - **The triangle is the user's choice** (2026-11-12, on the iPhone): a sign that the row unfolds, in the column the dot already has, so a row with children and one without line their dots up without giving width to either. Its own inline SVG in `AgentRow`, not Lucide's `play`, which reads as "play". The cost: the dot of a row with children folds, the same drawing that opens the chat on a row without; the triangle, only where it folds, tells them apart.
  - **Rejected: the chevron on the left, before the dot, as Mail groups a thread** (040, until 051), Lucide's `chevron-right` at 18 px in a column of 60 px that every row kept. Its reason still holds: on the user's iPhone on 2026-11-10 (029), the arrow at the row's right edge read as iOS's "go into" chevron, so the user took it for the way to the chat, and nothing sits on the right edge now but the folded row's marks and the time. Before that, until the review of 2026-11-10, it was the text `▸`/`▾` in `--muted`, about 5 pt on the iPhone 17e: it read as a bullet, almost unseen.
  - **Rejected: Mail's count, `3 ›` in grey on the right**, captured in the simulator (Checked live). It lines the dots up for free, but it puts back on the right edge the very `›` the user mistook for going to the chat.
  - **Its name says no branch**, unlike 038's `Subagents of <label>`: VoiceOver reads it right before its own row, in the same container, so two branches' `Show 1 subagent` do not mix (Checked live).
- **A folded row says what it hides**, on its right, before the time, inside the row's button: a small `StatusDot` of the hidden agents' attention, the highest of `waiting`, `failed`, `done` and `pending` (the ones that work say nothing, as upstream), then `+n`, the number hidden at every level (`src/lib/ui/Hidden.svelte`, shared with the chat's subagents line), `--inset` apart as there. Both are one `img` for VoiceOver, named by `hiddenName` (`3 subagents hidden, at least one waiting`), with the marks inside hidden from it, so the row is not read with a second loose status that sounds like the agent's own. They never shrink, so a long title gives way first and the attention never goes, as the chat's subagents line does. Together with the branch's rank, a waiting child is never hidden without a sign.
  - **A tap on them opens the chat** (051), like the rest of the row; only the dot's column folds. Until 051 they sat over the disclosure's column, deaf to touches, so a tap on `+n` folded. Rejected: under the title, after the place, where a long place would cut them off.
  - **No arrow goes with them**: Mail's `3 ›` stays rejected for its `›` (above).
- **The fold lives on the phone** (`src/lib/folds.ts`, `src/lib/folds.svelte.ts`): the unfolded panes of each machine and its `boot`, a module-level state, so it survives the chat and back but not closing the app, and a new `boot` (a server restart, whose pane ids are given again) starts it empty. What is not in the set is folded. Ignoring upstream's `collapsed` flag is on purpose, and the core does not even read it from the pane (Upstream gaps): it is shared by every client and born unfolded, so following it would leave the board full, and sending `collapse` from the phone would fold the Mac's sidebar too, and fight its reveal, which unfolds a parent when its hidden pane takes the focus. Rejected: a hybrid that also folds what the Mac folded, one more case for a flag that the folded default makes almost moot.
- **The order does not depend on the fold**: the core sorts the whole tree and the UI only hides rows, so folding or unfolding moves no branch.
- **A flow's team is named by its roles**, from the pane's `role` in the snapshot, never from the tab's name: a member under a pane with a role, its own not `orchestrator`, reads its role (`coder`, `reviewer`) on the first line and its title, or the agent's name, under it, as upstream (#378), since a team's rows otherwise read the same. The orchestrator keeps its title and adds ` · orchestrator` to its place. A member left as a root, or a pane without a role, reads as before.
- **An agent's in-process subagents** (`status`'s `subagents`, Claude Code's tasks) are not panes, cannot be opened and would muddle `+n` and the chat's subagents line; they are left out (Left out).

## Since when

- **From the `status` events, since the session has no time.** cornercase's `status` gives each pane's status, not when it took it (Upstream gaps); each `status` event carries its `time`. The `Store` keeps a record per pane (`board::Since`, Connection › Store) of the status the snapshots showed, its time if known, and an event heard ahead of them. An event of the status shown gives it its time; an event of another status waits ahead, and the rows do not change until a snapshot shows that status, which then takes the event's time. A snapshot that shows yet another status sets `(status, null)` and leaves the event ahead in place, since it may be a snapshot sent before the change. A pane gone from the snapshot leaves the record, except one only heard of and never shown, whose event may come before the first snapshot of a pane just made (a flow's subagent) and waits for it; a doubt drops it with every event ahead, so a pane that never shows does not stay. A restart empties the record. In the `Store` rather than in the forwarder, so the `agents` getter sees it too.
  - **Why an event waits for its snapshot**: `events` reaches the app at once and `status --follow` about 500 ms later, so the event of a change is the normal first news of it. Rejected: an event replacing the record at once, which left the row in its old status without a time for that half second, so it jumped to the top of its section and back, and a snapshot sent before the change then erased the event's time for good.
- **The limit**: the app knows the time only of the changes it saw. An agent already in its status when the app connects shows no time. When the app may have missed some events, every time is dropped and the statuses kept (`Since::doubt`): on each new `events` stream (a reconnection, the app back from the background, a network change) and on a `dropped` event. Otherwise a status that went and came back while the app was away would keep its first time, and look older than it is. Such an agent sorts first in its rank, which is right: it has been there at least as long as any time the app saw.
- **How it reads**: `now` under a minute, then `N min`, `N h` and `N d`, rounded down. A time ahead of the phone's clock, from a Mac whose clock is ahead, reads `now`. One timer every 30 s while the board is mounted gives every row the same `now`, and stops when it unmounts. Rejected: a timer per row.

## Live, without flicker

- **The rows go out only when they change** (Connection › Store › In the app), so a snapshot every 500 ms with the same rows redraws nothing.
- **The tree is still one flat list**, each row with its depth, so a branch that changes section slides as its rows, each by itself, keyed by pane as before. They go the same distance in the same `ENTER_MS`, so the branch moves as one block (Checked live).
- **One flat list of headers and rows**, keyed `section:<name>` and `pane:<id>`, with `animate:flip`. Svelte's `flip` moves an element only within its `{#each}`, so with one list per section a row going from Working to Waiting would vanish from one and appear in the other; in one list it slides to its new place, and the headers slide with it. Rejected: one list per section with `crossfade`, two transitions to keep in step for the same effect. The slide lasts `ENTER_MS`, 0 with Reduce Motion.
- **Before the first snapshot** (`agents` is `null`: connecting, or after a restart) the screen shows the mark, pulsing while it connects; with no agents, `No agents running.`

## A row

- **A button of at least 44 px** with an empty `ontouchstart` (Look › Touch and motion): the `StatusDot` (Look › Components), the title, the place under it in `--muted`, and the time on the right in tabular figures, so the digits do not jump as it counts; no time when `since` is `null`. A row with children adds the triangle under its dot, and a folded one the attention and `+n` before the time (Tree and folding).
- **The dot is 16 pt from the screen's edge**, as Issues' and Files' rows start: the list reaches `--inset` into the board's `--inset-wide` margin and the row pads `--inset` back. Every row starts with the same 14 px column, holding the dot, or, on a row with children, the status for VoiceOver under the fold's button (Tree and folding), so the dots of a level line up whether a row has children or not, and while searching. The times line up on the right.
- **16 pt from the dot to the title** (`--inset-wide`), not the 12 between the row's other parts: a 44 pt target centred on the dot spans from 1 to 45 pt, so with 12 the title, at 42, would start under it; at 46 it starts clear.
- **Rejected: a column of 60 px on every row's left** (040, until 051), which held the disclosure and the folded row's marks, so the dots lined up in one column. It cost 60 px of title on every row and put the dot about 88 pt from the edge. On the user's iPhone on 2026-11-12 the width weighed more than an empty column ("la lista de agentes deja mucho espacio a la izquierda, ocupemos todo"), and the user chose the triangle under the dot, which lines the dots up without it.
  - **Rejected before it: the column only on rows with children**, whose dots moved with the width of `+n` and the attention, about 50 pt between a root with `› ! +3` and one without, and zigzagged between siblings. And 038's empty slot on the right, which lined the times up with the arrow there and went with it.
- **A tap opens the agent's screen** (`router.go({ name: 'agent', machine, pane })`, Look › Navigation): the chat (`design/chat.md`), whose header is read by pane from the latest rows, so while the agent works its dot keeps changing there too, the back button (`‹ Agents`), and a `Terminal` button while it has its row, which opens the agent's pane in the terminal over it, fitted to the phone (Terminal › The grid › Opening it, Terminal › Fitted by default). A pane no longer among the rows, or a route opened on another machine (Look › Navigation), says `This agent is no longer running.` under the bar and its back button (Chat › Gone). Before the first list (`agents` is `null`: connecting, a new `Store`, a restart) the screen does not know yet, so it shows the board's mark, pulsing while it connects, rather than saying the agent is gone.
- **`Start`**, a primary button over the sections, opens the start screen (`design/starting-work.md`); it rests while the connection is not `connected`.
- **The board's `h1` is `Agents`, for screen readers only** (Look › Components): the connection bar already names the machine, and a visible title would repeat what the screen shows.

## Search

- **A field above the sections**, under `Start` (`src/lib/ui/SearchField.svelte`, shared with Issues and Files, Look › Components), named and placeheld `Search agents`, shown only while there is an agent. It scrolls with the list, as Mail's or Settings' does. Rejected: hidden until the list is pulled down, as in Mail, since the page scrolls in a WKWebView with its bounce, where pulling to show is fragile and nobody finds it; and sticky under the connection bar, a fixed height taken from a small screen for something used now and then.
- **Local**, over the rows already on the phone (`src/lib/board.ts`): nothing goes to the Mac, and nothing new is needed from upstream.
- **What matches**: each word of the query, split on spaces, must be inside one of the row's title, agent's name, project, workspace or role, so a team's member is found by the role it reads as. Case and accents count on neither side: both are lower-cased, decomposed (NFD) and stripped of their marks (`\p{M}`), so `cafe` finds `Café` and `ÁRBOL` finds `arbol`. A query of spaces does not filter.
- **The tree is pruned, not flattened**: what matches and every ancestor of it, so a child still reads under its parent, indented, in its root's section and in the core's order; a section left empty is not drawn. An ancestor that does not match reads like one that does: the simulator's captures did not ask for it dimmed.
- **Nothing is folded while searching**: a child that matches shows under a folded parent, and the rows draw no triangle and no `+n`, each its dot in the same column as off the search, so no dot moves as the query is typed. The unfolded set (`folds`) is not touched, so clearing the search brings the board back as it was. Rejected: folding inside the results, one more state for a list already short; Mail's search too lists the messages, not the threads.
- **`Cancel`** shows on the field's right while it has the focus or text; it clears it, drops the focus and brings the whole board back. The keyboard's search key (`enterkeyhint="search"`) drops the focus and keeps the query, so the keyboard goes and the results stay. When nothing matches, `No agent matches the search` replaces the sections under the field, which stays to fix the query.
- **The query lives on the phone, per machine** (`src/lib/boardSearch.ts`, `src/lib/boardSearch.svelte.ts`), a module-level state like the fold: it survives the chat and `‹ Agents`, but not closing the app; another machine sees none, and typing there replaces it; coming back before that shows it again, since only one query is kept and looking at another machine writes nothing. Rejected: clearing it on every switch of machine, one more effect for a query the user can clear with `Cancel`. While the list is `null` or empty the field hides and the query stays. A row that changes while searching comes into the results or goes out of them, sliding with `animate:flip` as any row.

## Left out

- The agents of the other servers a Mac links (`status`'s `machines`, gpui's `machine_agents.rs`): their ids belong to another server, and the app's `Snapshot` does not read them.
- Notifications, folding the sections, and filters by status or by project.
- Searching what the agents said (upstream's `search`): the board's search reads the rows' names only (Search).
- Issues' search telling accents apart, unlike the board's: making it ignore them is another behaviour, for its own change.
- The chat's subagents line (`src/routes/agent/Subagents.svelte`) keeps its arrow on the right, which unfolds the children in place: the user's complaint was about the board. It is the one row left whose right-edge chevron does not navigate (Look › Touch and motion).
- Folding or unfolding every branch at once, a setting for the default fold, and upstream's `collapsed` (Tree and folding).
- An agent's in-process subagents (`status`'s `subagents`, #358 upstream) as rows or as a number on the row.
