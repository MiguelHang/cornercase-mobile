# Starting work

New work on the Mac from the phone: an agent with a prompt, in a workspace that is already open or in its own worktree (tasks 023 and 045), or an agent or a flow on an issue of any connected tracker (tasks 024, 045 and 047). Code: `crates/core/src/cli/agents.rs` (`account list --check --json`), `crates/core/src/cli/start.rs` (the argv and the ids that answer), `src-tauri/src/commands/start.rs`, `src/lib/startForm.svelte.ts`, `src/lib/startAccounts.svelte.ts` (the accounts, task 052) and `src/routes/start/`; for the issues, `crates/core/src/cli/issues.rs` (their argv and answers), `src-tauri/src/commands/issues.rs`, `src/lib/issueSweep.ts` (which trackers to list and how their lists join), `src/lib/issues.svelte.ts` and `src/routes/issues/`; for the flows, `crates/core/src/cli/flows.rs`, `src-tauri/src/commands/flows.rs`, `src/lib/flowStart.svelte.ts` and `src/routes/start/FlowPicker.svelte`. Upstream's `StartArgs` and `NewWorkspaceArgs` (`src/cli/args.rs`) and gpui's `src/sidebar/forms/agents.rs` were read on `main` on 2026-11-09; upstream's `issue` commands (`src/cli/args/issue.rs`, 0.13.28) and gpui's issues panel (`src/panels/issues/`) on 2026-11-10, and upstream's `App::issue_sources`, `App::places` (`src/app/trackers.rs`) and `design/issues.md` on 2026-11-10 for task 045; `flow list --json` and `flow run --json` were run against 0.13.31 on 2026-11-10 for task 047 (the fixtures `flow-list/0.13.31/` and `flow-run/0.13.31/`); `account list --check --json` was run against 0.13.31 on 2026-11-12 for task 052 (the fixtures `account-list/0.13.31/`), and upstream's `ProfileArg` (`src/cli/args/accounts.rs`) and `AccountsInfo` read on `main` (0.13.46) the same day.

## No workspace without an agent

- **Task 023's `Workspace` action, `new-workspace --project <id> [--worktree] --json -- <name>`, left in 045**, with its form, its command, its `Workspace <name> created` toast and its line in `contract::REQUIRED`. A workspace without an agent has no row, and the phone opens a workspace only through an agent's row (the terminal needs the row; `Changes` and `Files` sit in the agent's header), so what it made could not be seen or used from the phone, as the user found on his iPhone (029, 2026-11-10). An agent is now started in a workspace that is open already (`start --workspace`) or in its own worktree. The bridge's allowlist keeps `new-workspace`, since it mirrors upstream's commands, not the app's (Bridge).

## The screen

- **A screen of its own, `start`, pushed over the board** by the board's `Start` button, or over an agent by its `New agent` (Starting from an agent), both resting while the connection is not `connected` (Look › Navigation). Rejected: the ticket's sheet from the bottom, since the prompt always opens the keyboard and WKWebView covers what is fixed at the bottom (Look › Forms).
- **Two actions, `Agent` and `Issue`**, two buttons with `aria-pressed` (`Segmented`, which the issue's `Agent` and `Flow` share) that switch between two forms (`AgentForm`, `ShowIssues`), each with its own button; until 045 a third, `Workspace` (No workspace without an agent). One `StartForm` holds them, and the issue's form (`IssueForm`) when Start opens with an issue, which hides the actions. `Issue` only says what it shows and opens the issues of every project (From an issue).
- **Checked before sending**, each error under its field: a workspace, an agent, a prompt that is not only spaces, a branch with `Own worktree`; for an issue, where it starts and an agent, or a flow (With a flow). A server is not asked what the phone can tell.
- **While it sends**, the button shows the spinner and `Starting…`, the fields rest, and nothing can send again. Outside `connected`, the buttons rest and a line says that what was typed stays until the app connects.
- **A refusal keeps everything typed** and shows cornercase's reason over the button, its stderr without `Error:` (`CommandError::reason`), not only in a toast: `--worktree` in a folder that is not a repository's root, for one, which the session cannot tell beforehand.
- **`Unanswered` is never retried**: the line may have run. It says that the agent may have started, and to look before trying again. A job the queue skipped (`Skipped`, its line never written, after a reconnection) is `not_sent`, `nothing was sent`, as in the chat: it surely did not run, so sending again is safe. The pickers say `cornercase did not answer.` when reading the agents or the workspaces is left unanswered.

## Starting from an agent

- **`New agent`** (icon `plus`, named for VoiceOver), the fourth icon of the agent's bar after `Terminal`, `Changes` and `Files` (Chat › The header stays at the top), pushes `start` with the agent's workspace (`{ name: 'start', machine, workspace }`), which the form chooses before reading the session (`StartForm.prefer`); it rests outside `connected` like the board's `Start`. It is the usual case from a phone: another agent beside the one being followed, on the same code. `Back` returns to the agent.
- **In the bar, not in the large header** (P3): measured on 2026-11-10 (Chat › The header stays at the top), the four icons leave the compact line 146 pt on a 390 pt phone and 131 pt on a 375 pt one, so a title is cut short (`Fix the l…`) but nothing overlaps, and the button is in reach while the thread scrolls. Rejected: a button under the title in the large header, which scrolls away with it.

## After it starts

- **The agent's screen is all that stays over the board** (`router.settle`, `{ name: 'agent', machine, pane, starting: true }`, on the start route's `machine`), so `Back` goes to the board and not to a form already sent, nor to the issue and the list it came from (From an issue). Started from the board, the form was the only screen over it, as 023's start screen did when it replaced the top route; started from an agent, that agent's screen goes too, and is a tap away on the board. A `warning` in the answer shows as an `info` toast. `Back` still works while it sends; if the start screen is no longer on top when the answer comes, only a toast says it started (`<agent> started`), so the answer never closes or replaces a screen opened since.
- **`Starting <agent>…`** with the spinner, until the pane's row comes in `agents-changed`: at the answer, the pane holds no agent yet, and the rows list only panes with one. Without it, the screen would say `This agent is no longer running.` at the first list (Chat › Gone). While it starts, a list without the pane does not count it as gone; once its row was seen, the usual rules hold, and another machine still ends it. Rejected: staying on the form until the row comes, with a limit, since a project's setup can take minutes and the form would be held all that time.
- **No limit on the wait**: if the agent never starts (its setup fails, its command is not found), the screen keeps saying it starts, and `Back` goes to the board, where the tab's shell shows no row.
- **The agent's name is kept by `App`**, the last one started, since the route says only `starting`.

## The trust question

- With `accept_trust_prompts` off, cornercase's default, an agent in a new worktree (a new folder) asks first whether to trust it, and the prompt waits for the answer. It is answered from the phone with Enter in the chat's keys (017) or in the terminal (021); until those exist, the agent's screen has `Terminal` (020, passive), which shows the question but cannot answer it. `--placed` keeps it from holding the queue.

## Left out

- `--machine`, `--mode`, `--effort`, a tab's `--name`, profiles (`--profile`, also for a flow: With a flow), `queue add`, also with an issue (`queue add --issue`), and a flow without an issue, from Start's `Agent`.
- For issues: connecting a tracker or keeping a token on the phone, people to filter by (`issue people`), the workspace's name from the issue (`--workspace-name`, for an agent or a flow), a prompt of the user's own with the issue, for an agent (Upstream gaps) or a flow (`flow run --prompt`, With a flow), and opening the issue in the phone's browser or copying its link.
- For accounts: remembering the last one used (Which account is chosen), adding, renaming, logging in or changing the default from the phone (`account add`, `login`, `rename`, `use`), warning about tokens in the Mac's environment (`tokens`, which win over any account), and an account for `queue add` or a flow without an issue, which stay left out themselves.
- For flows: following a run (`flow runs`, `flow messages`, `flow files`), editing, importing or ordering flows and choosing the default one, their diagram, and a flow in an open workspace, which upstream does not make.
- Going back from the issues to Start opens a new form, on `Agent`, with the workspace of Where the choices come from.
- Starting an issue in an open workspace of a project whose folder is a repository's root: upstream's places give only a new worktree of it (Where).
- Opening the terminal of a workspace without an agent: the `terminal` route needs an agent's row.
